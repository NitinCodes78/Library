Recall JDBC

JDBC (Java Database Connectivity) provides an interface to connect to the DB, query the DB and process the result. The actual implementation comes from the database-specific driver:

DatabaseDriverClass
MySQLConnector/Jcom.mysql.cj.jdbc.Driver
PostgreSQLPostgreSQL JDBC Driverorg.postgresql.Driver
H2 (in-memory)H2 Database Engineorg.h2.Driver
public class DatabaseConnection {

    public Connection getConnection() throws Exception {
        Class.forName("org.h2.Driver");                                 // driver class loading
        return DriverManager.getConnection("jdbc:h2:mem:userDB", "sa", "");   // connection making
    }

    public void insertUser() {
        String sqlQuery = "INSERT INTO users(user_name, age) VALUES (?, ?)";
        try (Connection con = getConnection();
             PreparedStatement preparedQuery = con.prepareStatement(sqlQuery)) {
            preparedQuery.setString(1, "X");
            preparedQuery.setInt(2, 27);
            preparedQuery.executeUpdate();
        } catch (Exception e) {
            // exception handling
        }                                                               // closing of resources
    }
}

Connection, Statement, PreparedStatement and ResultSet are all interfaces provided by JDBC; each driver implements them.

The boilerplate problem

  • Driver class loading
  • DB connection making
  • Exception handling
  • Closing the connection and other objects (Statement, ResultSet ...)
  • Manual handling of the DB connection pool

JdbcTemplate: Spring takes care of the boilerplate

BoilerplateWhat JdbcTemplate does
Driver class loadingHandled at application startup (registered with DriverManager).
DB connection makingTaken care of whenever you execute a query.
Exception handlingPlain JDBC gives one vague, checked SQLException. JdbcTemplate translates it into granular unchecked exceptions such as DuplicateKeyException and QueryTimeoutException (package org.springframework.dao).
Closing resourcesAfter update or query, success or failure, it closes the resources or returns the connection to the pool.
Connection poolSpring Boot provides a default pool: HikariCP (default maximum pool size 10).

Tune the pool in application.properties:

spring.datasource.hikari.maximum-pool-size=10
spring.datasource.hikari.minimum-idle=5

Or define your own pool bean:

@Configuration
public class AppConfig {
    @Bean
    public DataSource dataSource() {
        HikariDataSource dataSource = new HikariDataSource();
        dataSource.setDriverClassName("org.h2.Driver");
        dataSource.setJdbcUrl("jdbc:h2:mem:userDB");
        dataSource.setUsername("sa");
        dataSource.setPassword("");
        return dataSource;
    }
}

Frequently used JdbcTemplate methods

MethodUse
update(String sql, Object... args)INSERT / UPDATE / DELETE
update(String sql, PreparedStatementSetter pss)INSERT / UPDATE / DELETE with explicit parameter setting
query(String sql, RowMapper<T>)Get multiple rows
queryForList(String sql, Class<T>)One column of multiple rows
queryForObject(sql, args, Class<T>)Get a single row
queryForObject(sql, Class<T>)Get a single value (count, max ...)
// insert / update / delete
String insertQuery = "INSERT INTO users (user_name, age) VALUES (?, ?)";
int rowsAffected = jdbcTemplate.update(insertQuery, "X", 27);

String updateQuery = "UPDATE users SET age = ? WHERE user_id = ?";
int rows = jdbcTemplate.update(updateQuery, 29, 1);

// with PreparedStatementSetter
jdbcTemplate.update(insertQuery, (PreparedStatement ps) -> {
    ps.setString(1, "X");
    ps.setInt(2, 25);
});

// multiple rows with a RowMapper
List<User> users = jdbcTemplate.query("SELECT * FROM users", (rs, rowNum) -> {
    User user = new User();
    user.setUserId(rs.getInt("user_id"));
    user.setUserName(rs.getString("user_name"));
    user.setAge(rs.getInt("age"));
    return user;
});

// one column of many rows
List<String> userNames = jdbcTemplate.queryForList("SELECT user_name FROM users", String.class);

// single row (BeanPropertyRowMapper maps columns to fields)
User user = jdbcTemplate.queryForObject("SELECT * FROM users WHERE user_id = ?",
        new BeanPropertyRowMapper<>(User.class), 2);

// single value
int userCount = jdbcTemplate.queryForObject("SELECT COUNT(*) FROM users", Integer.class);
Why JPA is still needed

JdbcTemplate removes the plumbing, but you still write SQL strings and map every column to a field by hand. An ORM (Object-Relational Mapping) framework removes that too: you work with objects and the framework generates the SQL. That is the job of JPA (the specification) and Hibernate (the most popular implementation), covered next.

Interview corner
JDBC vs JdbcTemplate vs JPA?

JDBC: low-level API, lots of boilerplate. JdbcTemplate: Spring helper that handles connections, resources and exceptions but you still write SQL. JPA: object-relational mapping, the framework generates SQL.

What is a connection pool and what is the Spring Boot default?

A set of reusable DB connections (opening one is expensive). Default is HikariCP, maximum pool size 10.

Why is a PreparedStatement better than concatenating SQL?

It prevents SQL injection and lets the DB reuse the parsed query.
