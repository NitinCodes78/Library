Spring Boot Security: Part 1 (Architecture)

Why we need Spring Security, where its filter chain sits, and the dependencies to add.

Why Spring Security?

There are various kinds of attacks (CSRF, CORS misuse, SQL injection, XSS) and we need to protect our resources from them. For that we need proper:

  • Authentication: verify who you are.
  • Authorization: check what you are allowed to do.

That is where Spring Boot Security comes into the picture.

Architecture

We have already seen what filters are and where they fit: the request passes the servlet container (Tomcat), the filter chain, then the DispatcherServlet, then interceptors, and finally the controller. Spring Security plugs into this by adding a Security Filter Chain among the servlet filters.

Inside the security filter chain (authentication)

UsernamePasswordAuthenticationFilter (one of the security filters)
1. Creates an Authentication object (username, password) and delegates to the AuthenticationManager
2. AuthenticationManager (ProviderManager) delegates to an AuthenticationProvider — default: DaoAuthenticationProvider
3. Loads the user through UserDetailsService
InMemoryUserDetailsManager or JdbcUserDetailsManager (username/password in DB)
4. Matches passwords with PasswordEncoder
incoming raw password is hashed and compared with the stored hash
5. On success the authenticated Authentication (username, roles) is stored in the SecurityContext
  • AuthenticationManager is the entry point; it just coordinates.
  • AuthenticationProvider holds the real logic for one authentication type. The default implementation validates a username/password.
  • UserDetailsService knows how to fetch a user (from memory, a DB, anywhere).
  • PasswordEncoder: passwords are hashed during registration, and during login the incoming raw password is hashed the same way and compared.
  • SecurityContext keeps the current user's authentication (for form login it is saved in the HTTP session through HttpSessionSecurityContextRepository).

Dependencies

If a Spring Boot project is already present, add:

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>     provides core features: authentication, authorization, security filters etc.
</dependency>
<dependency>
    <groupId>org.springframework.session</groupId>
    <artifactId>spring-session-jdbc</artifactId>               enables persistent session management using a relational DB
</dependency>

If setting up a new Spring Boot project, go to Spring Initializr (start.spring.io) and add Spring Web and Spring Security (add the JDBC session dependency only if you want sessions persisted in a relational DB).

Mechanisms we will walk through end to end

  1. Form login (stateful)
  2. Basic authentication (stateless)
  3. JWT (stateless)
  4. OAuth2: authorization code (stateful or stateless), client credentials (stateless), password grant (stateless; deprecated in OAuth 2.1)
  5. API key authentication (stateless), etc.
Interview corner
Authentication vs authorization?

Authentication proves identity (who are you); authorization decides permissions (what may you do). Authentication comes first.

How does Spring Security hook into a request?

Through the SecurityFilterChain, a chain of servlet filters (via DelegatingFilterProxy) that runs before the DispatcherServlet.

Role of AuthenticationManager, AuthenticationProvider, UserDetailsService?

Manager delegates to providers; the provider authenticates; UserDetailsService loads the user data used by the provider.
