Dynamic Bean Initialization

One interface, two implementations: how to tell Spring which one to inject, from a fixed name to a value in application.properties.

The problem: unsatisfied dependency

Order is an interface with two implementations, and the controller asks for an Order without saying which one.

public interface Order {
    public void createOrder();
}

@Component
public class OnlineOrder implements Order {
    public OnlineOrder() { System.out.println("Online Order Initialized"); }
    public void createOrder() { System.out.println("created Online Order"); }
}

@Component
public class OfflineOrder implements Order {
    public OfflineOrder() { System.out.println("Offline Order initialized"); }
    public void createOrder() { System.out.println("created Offline Order"); }
}

@RestController
@RequestMapping(value = "/api")
public class User {
    @Autowired
    Order order;                          // which one?

    @PostMapping("/createOrder")
    public ResponseEntity<String> createOrder() {
        order.createOrder();
        return ResponseEntity.ok("");
    }
}

The application fails to start with an UnsatisfiedDependencyException: Error creating bean with name 'user'. Both beans were created (you can see both "initialized" lines), but Spring cannot pick one to inject.

Fix 1: @Qualifier (static choice)

Give each bean a name and name the one you want at the injection point.

@Qualifier("onlineOrderObject")
@Component
public class OnlineOrder implements Order { ... }

@Qualifier("offlineOrderObject")
@Component
public class OfflineOrder implements Order { ... }

@RestController
public class User {
    @Qualifier("onlineOrderObject")
    @Autowired
    Order order;                          // always the online one
}

Both beans are still created at startup, but createOrder() now prints "created Online Order". The choice is hard-coded.

Fix 2: inject both and decide at runtime

If the decision depends on the request, inject both with their own qualifier and choose inside the method.

@RestController
@RequestMapping(value = "/api")
public class User {

    @Qualifier("onlineOrderObject")
    @Autowired
    Order onlineOrderObj;

    @Qualifier("offlineOrderObject")
    @Autowired
    Order offlineOrderObj;

    @PostMapping("/createOrder")
    public ResponseEntity<String> createOrder(@RequestParam boolean isOnlineOrder) {
        if (isOnlineOrder) {
            onlineOrderObj.createOrder();
        } else {
            offlineOrderObj.createOrder();
        }
        return ResponseEntity.ok("");
    }
}

Fix 3: decide once, from configuration (@Bean + @Value)

Remove @Component from the implementations and let a @Configuration class build the right one based on a property. Now only one of them is ever created.

@Configuration
public class AppConfig {

    @Bean
    public Order createOrderBean(@Value("${isOnlineOrder}") boolean isOnlineOrder) {
        if (isOnlineOrder) {
            return new OnlineOrder();
        } else {
            return new OfflineOrder();
        }
    }
}
application.properties
isOnlineOrder=false

With isOnlineOrder=false the log shows only "Offline Order initialized", and the endpoint prints "created Offline Order". The controller is simply @Autowired Order order;.

@Value

@Value injects values from various sources: a property file, environment variables or an inline literal.

@Value("false") boolean isOnlineOrder              // inline literal
@Value("${isOnlineOrder}") boolean isOnlineOrder   // from application.properties
@Value("${isOnlineOrder:false}") boolean flag      // with a default if the key is missing

Good to know

Fix 3 is the idea behind @ConditionalOnProperty and @Profile (next chapters), which express "create this bean only if..." in a cleaner, declarative way.

Interview corner
Two beans implement the same interface. How do you pick one?

@Primary for a default, @Qualifier("name") to choose explicitly, inject a Map<String, Order> or List<Order> to choose at runtime, or create only one using @Bean, @ConditionalOnProperty or @Profile.

What is the default name of a @Component bean?

The class name with a lowercase first letter (onlineOrder).
