@Entity
public class UserDetails {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String name;
    private String email;
    public UserDetails() { }
    public UserDetails(String name, String email) { this.name = name; this.email = email; }
    // getters and setters
}

@Repository
public interface UserDetailsRepository extends JpaRepository<UserDetails, Long> { }

@Service
public class UserDetailsService {
    @Autowired UserDetailsRepository userDetailsRepository;

    public void saveUser(UserDetails user) { userDetailsRepository.save(user); }
    public List<UserDetails> getAllUsers() { return userDetailsRepository.findAll(); }
}

@RestController
@RequestMapping(value = "/api/")
public class UserController {
    @Autowired UserDetailsService userDetailsService;

    @GetMapping(path = "/test-jpa")
    public List<UserDetails> getUser() {
        userDetailsService.saveUser(new UserDetails("xyz", "xyz@conceptandcoding.com"));
        return userDetailsService.getAllUsers();
    }
}

The first three steps below happen during application startup; step 4 and 5 happen when an API is invoked.

1 and 2. EntityManagerFactory

  • Using the persistence unit configuration, the EntityManagerFactory object is created at application startup. If any property is not provided, a default is picked.
  • One EntityManagerFactory per persistence unit.
  • It acts as a factory to create EntityManager objects.
  • Spring Boot builds it through LocalContainerEntityManagerFactoryBean.createNativeEntityManagerFactory(), which finds the PersistenceProvider (Hibernate) and calls createContainerEntityManagerFactory(persistenceUnitInfo, properties).

What if we want to create it manually?

@Configuration
public class AppConfig {

    @Bean
    public DataSource dataSource() {
        HikariDataSource dataSource = new HikariDataSource();
        dataSource.setDriverClassName("org.h2.Driver");
        dataSource.setJdbcUrl("jdbc:h2:mem:userDB");
        dataSource.setUsername("sa");
        dataSource.setPassword("");
        return dataSource;
    }

    @Bean
    public JpaVendorAdapter jpaVendorAdapter() {
        HibernateJpaVendorAdapter adapter = new HibernateJpaVendorAdapter();
        adapter.setGenerateDdl(true);
        adapter.setDatabasePlatform("org.hibernate.dialect.H2Dialect");
        return adapter;
    }

    @Bean
    public LocalContainerEntityManagerFactoryBean entityManagerFactory(
            DataSource dataSource, JpaVendorAdapter jpaVendorAdapter) {
        LocalContainerEntityManagerFactoryBean emf1 = new LocalContainerEntityManagerFactoryBean();
        emf1.setDataSource(dataSource);
        emf1.setJpaVendorAdapter(jpaVendorAdapter);
        emf1.setPackagesToScan("com.conceptandcoding.learningspringboot.jpa");
        emf1.setPersistenceUnitName("uniqueFactoryName");     // unique name for our EntityManagerFactory
        return emf1;
    }
}

3. Transaction manager association

In the persistence unit we specify the transaction-type:

  • RESOURCE_LOCAL (default): a manager handling transactions for one database (Spring's JpaTransactionManager).
  • JTA (Java Transaction API): a manager handling a transaction that can span multiple databases (needs things like Atomikos, XADataSource and the two-phase commit protocol).

After the EntityManagerFactory is created, the matching transaction manager is created. (JTA is a topic of its own and is out of scope here.)

4. EntityManager and PersistenceContext (at request time)

EntityManager:

  • An interface in JPA with the methods to perform CRUD on entities: persist() (save), merge() (update), find() (fetch), remove() (delete), createQuery() (run JPQL).
  • The methods are implemented by the JPA vendor (Hibernate). EntityManagerFactory creates the object.

PersistenceContext:

  • Think of it as a first-level cache.
  • For each EntityManager a PersistenceContext is created, holding the list of entities it is working on, and it also manages the lifecycle of the entity.

Insert / update / delete through the EntityManager are transaction-bound: it first checks that a transaction is open and throws an exception if not (TransactionRequiredException). Read operations are not transaction-bound. Add @Transactional and it works:

@Service
public class UserDetailsService {

    @PersistenceContext
    EntityManager entityManager;

    @Transactional
    public void saveUser(UserDetails user) {
        entityManager.persist(user);
    }
}

StateMeaning
New (Transient)Just created with new; the persistence context knows nothing about it.
Managed (Persistent)Tracked by the persistence context. Changes are detected and written to the DB at flush (usually commit): this is automatic "dirty checking".
RemovedScheduled for deletion; the row is deleted on flush.
DetachedWas managed but the context is closed or cleared; changes are no longer tracked until merge().
  • persist() makes a New entity Managed. find()/queries return Managed entities. remove() moves it to Removed.
  • flush() pushes pending changes to the database; detach(entity), close() or clear() make entities Detached; merge(entity) returns a Managed copy of a detached one.
Interview corner
EntityManagerFactory vs EntityManager?

The factory is heavy, thread-safe and one per persistence unit (created at startup). The EntityManager is lightweight and not thread-safe, created per unit of work, each with its own persistence context.

What is the persistence context?

The first-level cache and change tracker of one EntityManager: it keeps one instance per entity id and detects modifications to flush.

Why must save/persist run inside a transaction?

Writes are only flushed and made durable on commit; without an open transaction the EntityManager throws TransactionRequiredException.

persist() vs merge()?

persist() makes a new entity managed (the same object). merge() copies the state of a detached/new object onto a managed one and returns that managed copy.
