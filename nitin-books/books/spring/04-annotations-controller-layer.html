Controller Layer Annotations

@Controller, @RestController, @RequestMapping, @RequestParam, @PathVariable, @RequestBody and ResponseEntity: how a request reaches your method.

1. @Controller

Indicates that the class is responsible for handling incoming HTTP requests. It is a specialised @Component (declared with @Target(TYPE), @Retention(RUNTIME)), so component scanning picks it up.

2. @RestController

@RestController=@Controller+@ResponseBody

3. @ResponseBody

  • Says that the return value of the controller method is serialised into the HTTP response body (JSON by default).
  • Without it, in a @Controller, Spring treats the returned String as a view name and tries to resolve and render that view.

4. @RequestMapping

Maps a request to a class or method. Its main attributes:

  1. value / path: both are the same, the URL pattern.
  2. method: the HTTP method (RequestMethod.GET ...).
  3. consumes, produces: the media types accepted in the request and produced in the response.
  4. params, headers: map only when a given parameter or header is present.
@RequestMapping(path = "/fetchUser", method = RequestMethod.GET,
                consumes = "application/json", produces = "application/json")

@RequestMapping is itself annotated with @Mapping and works on both types and methods. The shortcuts @GetMapping, @PostMapping, @PutMapping, @DeleteMapping and @PatchMapping are just @RequestMapping with the method pre-set.

5. @RequestParam

Binds a query parameter to a controller method parameter.

http://localhost:8080/api/fetchUser?firstName=SHRAYANSH&lastName=JAIN&age=32
@RestController
@RequestMapping(value = "/api/")
public class UserController {

    @GetMapping(path = "/fetchUser")
    public String fetchUser(@RequestParam(name = "firstName") String firstName,
                            @RequestParam(name = "lastName", required = false) String lastName,
                            @RequestParam(name = "age") int age) {
        return "fetching user details based on first name = " + firstName
               + ", lastName = " + lastName + " and age = " + age;
    }
}

The framework automatically converts the request parameter's string value to the target type. Supported:

  1. Primitive types: int, long, float, double, boolean ...
  2. Wrapper classes: Integer, Long, Float, Double, Boolean ...
  3. String: request parameters are inherently strings.
  4. Enums.
  5. Custom object types: through a registered PropertyEditor (or a Converter).

Use required = false for an optional parameter, and defaultValue to give it a fallback.

Customising binding with a PropertyEditor

@RestController
@RequestMapping(value = "/api/")
public class UserController {

    @InitBinder
    protected void initBinder(WebDataBinder binder) {
        binder.registerCustomEditor(String.class, "firstName", new FirstNamePropertyEditor());
    }

    @GetMapping(path = "/fetchUser")
    public String fetchUser(@RequestParam(name = "firstName") String firstName) { ... }
}

public class FirstNamePropertyEditor extends PropertyEditorSupport {
    @Override
    public void setAsText(String text) throws IllegalArgumentException {
        setValue(text.trim().toLowerCase());     // trims and lower-cases the incoming name
    }
}

6. @PathVariable

Extracts a value from the path of the URL and binds it to a method parameter.

@GetMapping(path = "/fetchUser/{firstName}")
public String fetchUser(@PathVariable(value = "firstName") String firstName) {
    return "fetching and returning user details based on first name = " + firstName;
}
// GET /api/fetchUser/Shrayansh
@RequestParam vs @PathVariable

@PathVariable identifies a resource (/users/42). @RequestParam filters or tweaks a request (/users?city=Pune&page=2).

7. @RequestBody

Binds the body of the HTTP request (typically JSON) to a Java object, using Jackson.

public class User {
    @JsonProperty("user_name")          // JSON key differs from the field name
    String username;
    String email;
    // getters and setters
}

@PostMapping(path = "/saveUser")
public String saveUser(@RequestBody User user) {
    return "User created " + user.getUsername() + ":" + user.getEmail();
}
curl --location --request POST 'http://localhost:8080/api/saveUser' \
  --header 'Content-Type: application/json' \
  --data-raw '{ "user_name": "Shrayansh", "email": "sjxyztest@gmail.com" }'

8. ResponseEntity

Represents the entire HTTP response: status, headers and body.

@GetMapping(path = "/fetchUser")
public ResponseEntity<String> fetchUserDetails(@RequestParam(value = "firstName") String firstName) {
    String output = "fetched User details of " + firstName;
    return ResponseEntity.status(HttpStatus.OK).body(output);
}

More on status codes in the chapter ResponseEntity and Status Codes.

Interview corner
@Controller vs @RestController?

@RestController = @Controller + @ResponseBody on every method, so return values are written to the body (JSON). A plain @Controller returns view names (for server-rendered pages) unless you add @ResponseBody.

@RequestParam vs @PathVariable vs @RequestBody?

Query string value vs a segment of the URL path vs the whole request body deserialised from JSON.

What happens if a required @RequestParam is missing?

Spring throws MissingServletRequestParameterException and responds with 400 Bad Request.

What is the default JSON library and how do you rename a field?

Jackson. Use @JsonProperty("name") on the field or getter.
