@ConditionalOnProperty

Create a bean only when a property says so: feature toggles without touching the code.

The bean is created conditionally, meaning it may or may not be created.

The default behaviour

@Component
public class MySQLConnection { public MySQLConnection() { System.out.println("initialization of MySQLConnection Bean"); } }

@Component
public class NoSQLConnection { public NoSQLConnection() { System.out.println("initialization of NoSQLConnection Bean"); } }

@Component
public class DBConnection {
    @Autowired MySQLConnection mySQLConnection;
    @Autowired NoSQLConnection noSQLConnection;

    @PostConstruct
    public void init() {
        System.out.println("is MySQLConnection object Null: " + (mySQLConnection == null));
        System.out.println("is NoSQLConnection object Null: " + (noSQLConnection == null));
    }
}

Both beans are created and injected: both "is ... Null: false".

Two use cases

  1. We want to create only one bean, either MySQLConnection or NoSQLConnection.
  2. We have two components sharing the same codebase, but one needs MySQLConnection and the other needs NoSQLConnection.

The solution is @ConditionalOnProperty.

@Component
@ConditionalOnProperty(prefix = "mysql", name = "enabled", havingValue = "true")
public class MySQLConnection { ... }

@Component
@ConditionalOnProperty(prefix = "nosql", name = "enabled", havingValue = "true")
public class NoSQLConnection { ... }

@Component
public class DBConnection {
    @Autowired(required = false)          // the bean may not exist
    MySQLConnection mySQLConnection;

    @Autowired(required = false)
    NoSQLConnection noSQLConnection;
    ...
}
application.properties
mysql.enabled=true
nosql.enabled=false

Now only "initialization of MySQLConnection Bean" is printed, and the report shows MySQLConnection is not null and NoSQLConnection is null. Each deployment decides through its own application.properties.

Attributes worth knowing
  • havingValue: the value that makes the condition true (by default any value except false counts as a match).
  • matchIfMissing = true: create the bean even when the property is absent (handy for "on by default" features).
  • It also works on @Bean methods, not only on classes.
  • Spring Boot's own auto-configuration uses the same idea, with @ConditionalOnClass, @ConditionalOnMissingBean and so on.

Advantages and disadvantages

Advantages

  1. Toggling of features
  2. Avoids cluttering the application context with unnecessary beans
  3. Saves memory
  4. Reduces application startup time

Disadvantages

  1. Misconfiguration can happen
  2. Code complexity when overused
  3. Multiple beans with the same configuration cause confusion
  4. Complexity in managing
Interview corner
How do you enable a feature only in one environment?

Put a flag in that environment's properties file and guard the bean with @ConditionalOnProperty (or use a profile).

@ConditionalOnProperty vs @Profile?

@Profile is tied to the active profile name (environment-wide). @ConditionalOnProperty checks any single property value, so it suits fine-grained feature flags.

What happens to an @Autowired field when the conditional bean is not created?

The app fails to start unless the injection is optional (required = false, Optional<T> or ObjectProvider<T>).
