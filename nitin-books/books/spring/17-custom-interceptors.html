Custom Interceptors

Run code before and after a controller method: for every request, for selected URLs, or only for methods carrying your own annotation.

What is an interceptor?

It is a mediator that gets invoked before or after your actual code. We often need custom interceptors for caching, logging, authentication and similar cross-cutting work.

Helpful background: Java annotations and AOP (pointcut, proxy, interception).

Interceptor for requests before they reach a specific controller

Implement HandlerInterceptor and register it:

@Component
public class MyCustomInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {
        System.out.println("inside pre handle Method");
        return true;                 // true: continue to the controller; false: stop here
    }

    @Override
    public void postHandle(HttpServletRequest request, HttpServletResponse response, Object handler,
                           @Nullable ModelAndView modelAndView) throws Exception {
        System.out.println("inside post handle method");
    }

    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response, Object handler,
                                @Nullable Exception ex) throws Exception {
        System.out.println("inside after completion method");
    }
}

@Configuration
public class AppConfig implements WebMvcConfigurer {

    @Autowired
    MyCustomInterceptor myCustomInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(myCustomInterceptor)
                .addPathPatterns("/api/*")                                    // apply to these URL patterns
                .excludePathPatterns("/api/updateUser", "/api/deleteUser");   // exclude these
    }
}

Interceptor for requests only on methods carrying a custom annotation

Sometimes we do not want URL patterns; we want to mark particular controller methods and run the interceptor only for those.

Step 1: create a custom annotation

A custom annotation is created with the keyword @interface.

public @interface MyCustomAnnotation { }

public class User {
    @MyCustomAnnotation
    public void updateUser() {
        // some business logic
    }
}

Annotations can carry values. Rules for an annotation's "methods" (they behave like fields):

  • No parameters, no body.
  • The return type is restricted to: primitives (int, boolean, double ...), String, enum, Class<?>, other annotations, or an array of those.
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface MyCustomAnnotation {
    String key() default "defaultKeyName";
}

@MyCustomAnnotation(key = "userKey")
public void updateUser() { ... }

// all the allowed kinds together
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface MyCustomAnnotation {
    int intKey() default 0;
    String stringKey() default "defaultString";
    Class<?> classTypeKey() default String.class;
    MyCustomEnum enumKey() default MyCustomEnum.ENUM_VAL1;
    String[] stringArrayKey() default {"default1", "default2"};
    int[] intArrayKey() default {1, 2};
}
  • @Target says where the annotation can be placed (method, type, field ...).
  • @Retention(RetentionPolicy.RUNTIME) keeps it available at runtime, which the interceptor needs to read it.

Step 2: the interceptor checks for the annotation

In preHandle, the handler object is a HandlerMethod when the request maps to a controller method. Read the annotation from it:

@Component
public class MyCustomInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
        if (handler instanceof HandlerMethod handlerMethod) {
            MyCustomAnnotation annotation = handlerMethod.getMethodAnnotation(MyCustomAnnotation.class);
            if (annotation != null) {
                System.out.println("annotation present, key = " + annotation.key());
                // do the special work only for annotated methods
            }
        }
        return true;
    }
}

@GetMapping(path = "/getUser")
@MyCustomAnnotation(key = "userKey")
public String getUser() { ... }

Register the interceptor as before, usually with a broad pattern like /**, and let the annotation decide where the logic really applies.

Multiple interceptors and ordering

You can register many interceptors. They run in registration order for preHandle, and in reverse order for postHandle and afterCompletion.

@Override
public void addInterceptors(InterceptorRegistry registry) {
    // below order is maintained while calling the interceptors
    registry.addInterceptor(myCustomInterceptor1)
            .addPathPatterns("/api/*")
            .excludePathPatterns("/api/updateUser", "/api/deleteUser");
    registry.addInterceptor(myCustomInterceptor2)
            .addPathPatterns("/api/*")
            .excludePathPatterns("/api/updateUser");
}

If preHandle returns false, the next interceptor and the controller are not invoked at all. (You then write the response yourself, for example response.setStatus(401).)

Interview corner
What are the three methods of HandlerInterceptor?

preHandle, postHandle, afterCompletion.

How do you run an interceptor only for some endpoints?

URL patterns (addPathPatterns/excludePathPatterns) or a custom annotation read through HandlerMethod.

What if preHandle returns false?

The chain stops: no further interceptors, no controller. afterCompletion runs only for interceptors whose preHandle already returned true.
