AOP: Aspect Oriented Programming

Intercept a method call and run code before, after or around it, without touching the method itself.

What is AOP?

  • In simple terms, it helps to intercept a method invocation and perform some task before and after the method.
  • It lets us focus on business logic by moving boilerplate and repetitive code (logging, transaction management and so on) elsewhere.
  • An Aspect is a module that handles this repetitive code. It gives reusability and maintainability.

Typical uses: logging, transaction management, security, auditing, timing and caching.

The first aspect 
@RestController
@RequestMapping(value = "/api/")
public class EmployeeController {

    @GetMapping(path = "/fetchEmployee")
    public String fetchEmployee() {
        return "item fetched";
    }
}

@Aspect
@Component
public class LoggingAspect {

    @Before("execution(public String com.conceptandcoding.learningspringboot.EmployeeController.fetchEmployee())")
    public void beforeMethod() {
        System.out.println("inside beforeMethod Aspect");
    }
}

Calling /api/fetchEmployee prints "inside beforeMethod Aspect" first, and the browser shows "item fetched".

The vocabulary

TermMeaning
AspectThe class holding the cross-cutting logic (@Aspect)
Join pointA point where the actual method invocation happens
PointcutAn expression that tells where an advice should be applied
AdviceThe action taken: @Before, @After or @Around the method execution

Pointcut: the execution expression

Shape: execution(modifiers? return-type declaring-type? method-name(params) throws?). The access modifier is optional and can be omitted; the return type is mandatory (use * for "any").

ExpressionMatches
execution(public String com.x.Employee.fetchEmployee())exactly that method
execution(* com.x.Employee.fetchEmployee())any return type
execution(* com.x.Employee.*(String))any method of Employee with a single String parameter
execution(String com.x.Employee.fetchEmployee(*))fetchEmployee with any single parameter
execution(String com.x.Employee.fetchEmployee(..))fetchEmployee with 0 or more parameters
execution(String com.x..fetchEmployee())fetchEmployee in the package com.x and its sub-packages
execution(String com.x..*())any no-arg method in com.x and sub-packages
  • (*) wildcard matches any single item.
  • (..) wildcard matches zero or more items.

Types of pointcut designators

1. execution

Matches a particular method in a particular class (above).

2. within

Matches all methods within a class or package.

@Before("within(com.conceptandcoding.learningspringboot.Employee)")        // every method of Employee
@Before("within(com.conceptandcoding.learningspringboot..*)")              // every method in package + subpackages

3. @within

Matches any method in a class that carries a given annotation.

@Aspect
@Component
public class LoggingAspect {
    @Before("@within(org.springframework.stereotype.Service)")
    public void beforeMethod() { System.out.println("inside beforeMethod aspect"); }
}

@Service
public class EmployeeUtil {
    public void employeeHelperMethod() { System.out.println("employee helper method called"); }
}

Calling the controller, which calls employeeUtil.employeeHelperMethod(), prints the advice first, then "employee helper method called".

4. @annotation

Matches any method annotated with the given annotation.

@Before("@annotation(org.springframework.web.bind.annotation.GetMapping)")
public void beforeMethod() { ... }

5. args

Matches methods by their argument types.

@Before("args(String,int)")
public void beforeMethod() { ... }

// employeeUtil.employeeHelperMethod("xyz", 123)  -> advice runs

@Before("args(com.conceptandcoding.learningspringboot.Employee)")     // object type instead of primitive

6. @args

Matches methods whose argument's class carries a given annotation.

@Before("@args(org.springframework.stereotype.Service)")
// matches employeeHelperMethod(EmployeeDAO dao) when EmployeeDAO is annotated with @Service

7. target

Matches methods on a particular instance type (the proxied target object), including an interface.

@Before("target(com.conceptandcoding.learningspringboot.EmployeeUtil)")

// by interface: both implementations match
@Before("target(com.conceptandcoding.learningspringboot.IEmployee)")

public interface IEmployee { void fetchEmployeeMethod(); }
@Component("tempEmployee")  public class TempEmployee  implements IEmployee { ... }
@Component("permaEmployee") public class PermaEmployee implements IEmployee { ... }

Combining pointcuts

Use && (and), || (or) and ! (not).

@Before("execution(* com.x.EmployeeUtil.*(..)) && @annotation(com.x.Audited)")
public void beforeAndMethod() { System.out.println("inside beforeAndMethod aspect"); }

Named pointcuts

Define the expression once and reuse it by name.

@Pointcut("execution(* com.conceptandcoding.learningspringboot.EmployeeUtil.*(..))")
public void myPointcutName() { }

@Before("myPointcutName()")
public void beforeMethod() { System.out.println("inside beforeMethod aspect"); }

Advice types

AdviceRuns
@Beforebefore the method
@Afterafter the method, whether it returned or threw (like finally)
@AfterReturningonly after a successful return; can read the return value
@AfterThrowingonly if the method threw an exception
@Aroundsurrounds the method: before and after, and it controls whether the method runs at all

@Around receives a ProceedingJoinPoint; calling proceed() runs the real method.

@Aspect
@Component
public class TimingAspect {

    @Around("execution(* com.conceptandcoding.learningspringboot.EmployeeUtil.*(..))")
    public Object around(ProceedingJoinPoint joinPoint) throws Throwable {
        System.out.println("inside before Method aspect");
        Object result = joinPoint.proceed();            // the real method runs here
        System.out.println("inside after Method aspect");
        return result;                                  // always return what the method returned
    }
}

Output order: "inside before Method aspect", "employee helper method called", "inside after Method aspect". Forgetting to return the result (or to call proceed()) silently breaks the caller.

How does the interception actually work?

Two natural questions: how is the call intercepted? and with thousands of pointcuts, does every call get matched against all of them? The answer is that matching happens once, at startup, not on every call.

At application startup

  1. Spring looks for classes annotated with @Aspect.
  2. It parses the pointcut expressions (done by the PointcutParser class) and keeps them in an efficient data structure (a cache).
  3. It then looks at the @Component, @Service, @Controller ... classes and checks, for each, whether it is eligible for interception by any pointcut (done by AbstractAutoProxyCreator).
  4. If yes, it creates a proxy instead of the plain object, using a JDK dynamic proxy (when the class implements an interface) or a CGLIB proxy (subclass proxy).

The proxy contains the code that runs the advice before the method, then the method itself, then any after-advice. The proxy is what gets injected into other beans.

When a request arrives

Callercalls the beanProxy (JDK / CGLIB)runs the chain of adviceBefore adviceproceed()Real methodthenAfter advice
  • The caller actually calls the proxy. The proxy runs the matching advice in the chain: for example the first @Before, then the next advice, then the method execution, then the @After advice.
  • Only the classes that matched at startup are proxied, so non-matching beans cost nothing.
Gotchas (frequently asked)
  • Self-invocation: a call from one method to another method of the same class (this.other()) does not go through the proxy, so the advice does not run. The same reason @Transactional and @Async seem to "not work" inside the same class.
  • Spring AOP works only on Spring beans and only on public method calls through the proxy. Full AspectJ (compile/load-time weaving) removes these limits.
  • private and final methods (and final classes) cannot be proxied by CGLIB.
  • Use @Order on an aspect to control the order when several aspects match.
Interview corner
What is AOP, and where have you used it?

A way to separate cross-cutting concerns (logging, security, transactions, metrics) from business logic. Spring itself uses it for @Transactional, @Async, @Cacheable and method security.

Aspect vs advice vs pointcut vs join point?

Aspect: the module. Advice: the action. Pointcut: the expression choosing where. Join point: the actual method execution being intercepted.

JDK dynamic proxy vs CGLIB?

JDK proxies implement the target's interfaces; CGLIB generates a subclass of the target class. Spring Boot defaults to CGLIB (spring.aop.proxy-target-class=true).

Why doesn't my advice run on an internal method call?

Self-invocation bypasses the proxy. Move the method to another bean, or inject the bean into itself/use AspectJ.
