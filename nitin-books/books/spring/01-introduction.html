Introduction: Servlets, Spring and Spring Boot

Why Spring exists, what Spring Boot fixed, and the one idea everything else builds on: Dependency Injection.

First, the Servlet and the Servlet Container

  • It is the foundation for building web applications in Java.
  • A Servlet is a Java class that handles a client request, processes it and returns the response.
  • A Servlet Container (Tomcat is the popular one) is what manages the Servlets. Our application is deployed inside it.
Input requestarrives atServlet container (Tomcat)1. reads web.xml servlet mappingweb.xml2. invokes the matchingServlet3. responseClient

In the old days each servlet was a class like this, and the URL-to-servlet mapping was written by hand in web.xml:

@WebServlet("/demoservletone/*")
public class DemoServlet1 extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response) {
        String requestPathInfo = request.getPathInfo();
        if (requestPathInfo.equals("/")) {
            // do something
        } else if (requestPathInfo.equals("/firstendpoint")) {
            // do something
        } else if (requestPathInfo.equals("/secondendpoint")) {
            // do something
        }
    }

    @Override
    protected void doPut(HttpServletRequest request, HttpServletResponse response) {
        // do something
    }
}

What problems did the Spring Framework solve?

Problem with ServletsHow Spring solves it
web.xml grows huge over time and is hard to manage and understandAnnotation-based configuration, so no web.xml
The Servlet container creates the objects and controls their lifecycleInversion of Control (IoC): a more flexible way to manage object dependencies and lifecycle, done through Dependency Injection
Unit testing is harder: object creation belongs to the container, so mocking is not easyDependency injection makes mocking and unit testing very easy
REST APIs are awkward: handling HTTP methods, request parameters and path mapping makes the code hard to readSpring MVC gives an organised way to handle requests and build RESTful APIs

Spring also integrates with lots of other technology: Hibernate/JPA/JDBC, JUnit and Mockito, caching, messaging, security, asynchronous programming and more. Developers pick the combination that fits.

The most important idea: Dependency Injection (IoC)

Without dependency injection, a class creates the objects it needs itself:

public class Payment {
    User sender = new User();            // Payment builds its own User

    void getSenderDetails(String userID) {
        sender.getUserDetails(userID);
    }
}
public class User {
    public void getUserDetails(String id) { }
}

This is tight coupling: Payment is glued to User.

  • To unit-test getSenderDetails() you cannot easily mock User, because Payment creates a real one and so calls the real method.
  • If tomorrow there are different kinds of user (Admin, Member), you cannot swap the user dynamically.

With dependency injection, Spring creates the object and hands it in:

@Component
public class Payment {
    @Autowired
    User sender;                          // Spring resolves and injects it

    void getSenderDetails(String userID) {
        sender.getUserDetails(userID);
    }
}
@Component
public class User {
    public void getUserDetails(String id) { }
}
  • @Component tells Spring: "manage this class" (it becomes a bean).
  • @Autowired tells Spring: "resolve this dependency and put the object here".

The DispatcherServlet is the single front-door servlet. It chooses the controller, Spring creates an instance of that controller along with its dependencies, and the right API method is invoked.

The pain of plain Spring MVC

A classic Spring MVC project needed a lot of setup before the first API worked: servlet-api and spring-webmvc dependencies added one by one with matching versions, a config class and a dispatcher servlet initializer.

@Configuration
@EnableWebMvc
@ComponentScan(basePackages = "com.conceptandcoding")
public class AppConfig { }

public class MyApplicationInitializer
        extends AbstractAnnotationConfigDispatcherServletInitializer {

    protected Class<?>[] getRootConfigClasses() { return null; }

    protected Class<?>[] getServletConfigClasses() {
        return new Class[] { AppConfig.class };
    }

    protected String[] getServletMappings() {
        return new String[] { "/" };
    }
}

What Spring Boot fixed

1. Dependency management

No more adding many dependencies one by one and worrying about compatible versions. One parent plus starters:

<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.2.3</version>
</parent>
...
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>

2. Auto-configuration

No need to configure DispatcherServlet, AppConfig, @EnableWebMvc or @ComponentScan yourself: Spring Boot adds them internally by default.

@SpringBootApplication
public class SpringbootApplication {
    public static void main(String[] args) {
        SpringApplication.run(SpringbootApplication.class, args);
    }
}

3. Embedded server

In traditional Spring MVC you build a WAR file (your classes, JSP pages, configuration and dependencies) and deploy it to an external servlet container such as Tomcat. In Spring Boot the servlet container is already embedded: just run the application.

Hello world: a whole API in a few lines 
@RestController
@RequestMapping("/myapi")
public class MyController {

    @GetMapping("/firstapi")
    public String getData() {
        return "Hello from concept and coding";
    }
}
// GET localhost:8080/myapi/firstapi  ->  Hello from concept and coding

So, what is Spring Boot?

  • A quick way to create a production-ready application.
  • It is built on top of the Spring Framework.
  • It follows Convention over Configuration: sensible default values are used, and a developer who wants something different can override them.
  • It helps you run an application as quickly as possible.

Spring vs Spring Boot?

Spring is the framework (IoC, DI, MVC, data, security ...). Spring Boot is an opinionated layer on top of it: starters for dependencies, auto-configuration, an embedded server and production features, so you write far less setup code.

What is IoC and how is it different from DI?

IoC is the principle: the framework, not your code, controls object creation and wiring. Dependency Injection is the technique used to achieve it: the container injects the dependencies into the object.

Why is constructing a dependency with new a problem?

It creates tight coupling: you cannot mock it for tests or swap the implementation without editing the class.

What does @SpringBootApplication combine?

@SpringBootConfiguration (a configuration class), @EnableAutoConfiguration and @ComponentScan.
