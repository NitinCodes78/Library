List: ArrayList, LinkedList, Vector, Stack

Ordered collections you can reach by position.

Gets all the methods of the Collection interface, plus its own:

List<Integer> list = new ArrayList<>();      // ArrayList: a concrete class which implements List
list.replaceAll((Integer val) -> -1 * val);
list.sort((Integer val1, Integer val2) -> val1 - val2);

ListIterator

ListIterator<E> listIterator() extends Iterator, so it has hasNext(), next(), remove() and new methods that help to iterate in the backward direction:

MethodWhat it does
boolean hasPrevious()is there an element behind the cursor?
E previous()returns the previous element and moves the cursor position backward (throws an exception if none)
int nextIndex()index of the next element (returns the size of the list if it's at the end)
int previousIndex()index of the previous element (returns -1 if it's at the start)
add(E e)inserts the element immediately before the element that would be returned by next and after the element that would be returned by previous. A subsequent call to next() is not impacted.
set(E e)replaces the last element returned by next or previous with the given element

listIterator(int index) starts the iterator from a specific index. That index indicates the first element that would be returned by an initial call to next.

Where is the cursor?

Basically it does not stand at any element, it stands between two elements.

▼
100
-10

Initially the pointer is before the first element. After next() it moves forward by one: the previous element is 100, the next is -10.

100
-3
-10

While iterating, lit.add(-3) puts -3 behind the cursor: now previous = -3 and next is still -10 (the subsequent call to next() is not impacted).

ListIterator<Integer> lit = list.listIterator();
while (lit.hasNext()) { /* ... */ }

// to start from the end (or any index):
ListIterator<Integer> listIterator = list.listIterator(list.size());
while (listIterator.hasPrevious()) {
    listIterator.previous();      // walks backward
}

ArrayList

Internally uses an array (and in Java, Array is also a child of the Object class).

Time complexity

OperationCostWhy
Insertion at the endO(1)space is sufficient
Insertion at a particular indexO(n)shifting of values is required
Insertion when the array is fullO(n)the array size threshold is reached; values are copied to a bigger array
DeletionO(n)we have to shift the values
Access by index (get)O(1)direct array position
Search for a value (contains, indexOf)O(n)every element may have to be checked

ArrayList is also not thread-safe. The thread-safe version is:

List<Integer> list = new CopyOnWriteArrayList<>();

LinkedList

Implements both Deque and List (clear from the collections hierarchy). Supports the methods of both Deque and List.

Time complexity

  • Insertion and deletion at the start and end: O(1).
  • Search, insertion and deletion at a particular index: O(n), for the lookup of the index.

LinkedList is not thread-safe.

ArrayList or LinkedList?

Default to ArrayList: it's compact in memory, and index access is O(1). LinkedList only wins when you add or remove at the ends (or through an iterator) all the time. For queues and stacks, ArrayDeque is usually even better.

Vector

  • Exactly the same as ArrayList: elements can be accessed via index.
  • But it's thread-safe: it puts a lock when an operation is performed on the Vector.
  • Less efficient than ArrayList, as for each operation it does lock/unlock internally.
Vector<Integer> obj = new Vector<>();

Stack is a child of Vector (so also thread-safe). Deque is recommended for DSA stack and queue problems: it's faster.

Interview corner
ArrayList vs LinkedList?

ArrayList: array-backed, O(1) get by index, O(n) insert in the middle. LinkedList: node-based, O(1) at the ends, O(n) to reach an index.

ArrayList vs Vector?

Vector is synchronized (thread-safe but slower) and legacy; ArrayList is not synchronized.

How does an ArrayList grow?

When full, it allocates a bigger array (about 1.5 times) and copies the old elements, so an add is amortized O(1).

Iterator vs ListIterator?

ListIterator works only on Lists, moves both ways, and can add and set while iterating.
