LinkedHashMap, TreeMap and Sets

Ordered maps, sorted maps, and sets that quietly use a Map inside.

LinkedHashMap

extends HashMap<K,V> implements Map<K,V>

  1. Helps to maintain insertion order or access order.
  2. Similar to HashMap, but also uses a doubly linked list.

Suppose map.put(1,"A"); put(21,"B"); put(23,"C"); put(141,"D"); put(25,"E");

bucket 0
1 "A" → 21 "B"
bucket 1
23 "C" → 25 "E"
bucket 2
141 "D"

Buckets work exactly as in HashMap (the next pointers), and every node also has before and after pointers that string all entries together in insertion order: A ↔ B ↔ C ↔ D ↔ E.

In LinkedHashMap, Map.Entry<K,V> extends HashMap.Node<K,V> and it contains before and after extra, in addition. It's also an array of Nodes, calculates the hash and then index and stores elements accordingly, but also maintains before and after pointers, in addition to HashMap, to maintain the insertion order.

Access order

By default it gives insertionOrder = true and accessOrder = false. With accessOrder = true:

Map<Integer, String> map = new LinkedHashMap<>(16, .75F, true);
//                                          initial capacity ^   ^ load factor  ^ accessOrder
map.get(21);      // O(1), and moves that node to the last
12123get(21)12321
Good to know: an LRU cache in a few lines 
class LRU<K,V> extends LinkedHashMap<K,V> {
    private final int max;
    LRU(int max) { super(16, 0.75f, true); this.max = max; }
    @Override
    protected boolean removeEldestEntry(Map.Entry<K,V> eldest) {
        return size() > max;      // drop the least recently used
    }
}

A classic interview question: access order moves used entries to the end, so the eldest is the least recently used.

Time complexity (amortized)

O(1) for get(), put(), remove(), containsKey().

It's not thread-safe and there is no thread-safe version available. So we have to explicitly make this collection thread-safe like this:

Map<Integer, String> map2 = Collections.synchronizedMap(new LinkedHashMap<>());

TreeMap

Map (interface)
SortedMap extends Map (interface)
NavigableMap extends SortedMap (interface)
TreeMap implements it (class)
  • Sorted according to the natural ordering of the key, or by a Comparator provided during map creation.
  • Based on a red-black tree (a self-balancing BST).
  • O(log n) time complexity for insert, remove and get operations.

Node structure: [ Left | Parent | Key | Value | Right ]

SortedMap methods

SortedMap<K,V> headMap(K toKey);      // keys strictly less than toKey (exclusive)
SortedMap<K,V> tailMap(K fromKey);    // keys from fromKey onwards (inclusive)
K firstKey();
K lastKey();

SortedMap<Integer, String> map2 = new TreeMap<>(
        Map.of(21, "SJ", 11, "PJ", 13, "RJ", 5, "TJ")      // Map.of supports up to 10 entries
);
// sorted keys: 5, 11, 13, 21
System.out.println(map2.headMap(13));    // {5=TJ, 11=PJ}      13 exclusive
System.out.println(map2.tailMap(13));    // {13=RJ, 21=SJ}     13 inclusive
System.out.println(map2.firstKey());     // 5
System.out.println(map2.lastKey());      // 21

Also check certain methods in NavigableMap once: lowerEntry(K key), lowerKey(K key), floorKey(K key), navigableKeySet(), pollFirstEntry(), pollLastEntry() and many more.

Good to know

TreeMap does not allow a null key (it must compare keys), and it compares keys with compareTo/the comparator, not equals(). Handy: floorKey(x) = greatest key ≤ x, ceilingKey(x) = smallest key ≥ x.

Set (internally uses a Map)

A Set does not contain duplicate values (only one null value you can insert, in HashSet).

HashSet

  • Data structure used: HashMap: HashMap<E, Object> map = new HashMap<>();
  • During the add method, it stores the element in the key part, and in its value it stores a dummy object: map.put(element, PRESENT), where PRESENT is a single shared constant (private static final Object PRESENT), so no extra object is created per element.
  • It's not thread-safe. The newKeySet method present in the ConcurrentHashMap class is used to create a thread-safe set.

Thread-safe version

Set<Integer> threadSafeSet = ConcurrentHashMap.newKeySet();

Without thread-safety, adding an element while iterating:

Iterator<Integer> it = set.iterator();
while (it.hasNext()) {
    int val = it.next();
    if (val == 1) set.add(11);     // ✗ gives ConcurrentModificationException
}                                  // while iterating we can only remove (it.remove()), not add

LinkedHashSet

  • Internally it uses LinkedHashMap. O(1).
  • Maintains the insertion order of the elements.
  • Not thread-safe, but can be made so: Set<Integer> set = Collections.synchronizedSet(new LinkedHashSet<>());
  • Can't maintain access order here like LinkedHashMap, as there is no option to pass that variable in the parameter.

TreeSet

  • Internally it uses TreeMap. O(log n).
  • It cannot store a null value.
  • Elements stay sorted (natural order or a Comparator).

Interview corner
How does HashSet reject duplicates?

It stores each element as a HashMap key. put of an existing key (same hash, equals() true) doesn't add a new entry, so add() returns false.

How do you implement an LRU cache?

A LinkedHashMap with accessOrder = true and an overridden removeEldestEntry.

HashMap vs TreeMap?

HashMap: O(1), unordered, allows one null key. TreeMap: O(log n), sorted by key, no null key, and has range methods like headMap/tailMap.

Two sets: how do you get union, intersection, difference?

addAll, retainAll, removeAll (on a copy).
