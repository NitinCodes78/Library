Project Lombok

Let annotations write the boilerplate.

A Java library which helps to reduce boilerplate code using annotations. During compilation, it processes the annotations and injects code into our Java classes (works from Java 6 onwards).

import lombok.val;
public static void main(String[] args) {
    val temp = "hello";        // IntelliJ may show an error here...
    System.out.println(temp);  // ...but it compiles properly and temp is printed
}

It's because Lombok adds the code during compile time, but our IDE does not see the code which Lombok generates, so it shows a red error even though compilation works fine. In the .class file it is simply String temp = "hello";.

IDE setup

We may have to add the Lombok plugin to our IDE and enable annotation processing so that the IDE simulates what Lombok generates.

Most used features

1. val and var

Instead of actually writing the type, we can use these as the type of a local variable declaration. The type will be inferred from the initializer expression. Works only for local variables (not for fields or parameters).

  • val: marks the local variable immutable (variable made final).
  • var: local variable not marked as final.
val a = 10;       // initialization is required, as it infers the type from that itself
a = 30;           // cannot assign, as it's final

var b = 10;
b = 30;           // fine
Good to know

Since Java 10 the language itself has var, so Lombok's var is rarely needed.

2. @NonNull

Throws NPE if the value is null. Can be used on parameters of a method or constructor.

void func(@NonNull String name) {
  System.out.println(name);
}
→ in the .class →
void func(@NonNull String name) {
  if (name == null) { throw new NullPointerException(...); }
  System.out.println(name);
}

3. Getters and setters

class Test {
    @Getter @Setter
    String name;

    @Getter @Setter
    boolean flag;
}

By default getters and setters are public, but we can control it:

@Getter(AccessLevel.PRIVATE) @Setter(AccessLevel.PROTECTED)
String name;

It can be applied at class level too; then:

  • @Getter will be applied to all non-static fields.
  • @Setter will be applied to all non-static and non-final fields.

While using the annotation at class level, if we want to skip the default generation for any field, we can do that by using AccessLevel.NONE:

@Getter @Setter
public class Test {
    @Setter(AccessLevel.NONE)
    String name;
    // other fields ...
}

4. @ToString

@ToString
public class TestPo {
    String name;
    boolean flag;
}
// class file gets: public String toString() { ... }

Excluding any specific field:

@ToString.Exclude
boolean flag;

5. Constructors

AnnotationGenerates
@NoArgsConstructora no-args constructor
@RequiredArgsConstructora constructor with only final and @NonNull fields
@AllArgsConstructora constructor with all fields

6. @EqualsAndHashCode

By default, it uses all non-static and non-transient fields.

7. @Data

A shortcut for:

  • @ToString
  • @EqualsAndHashCode
  • @Getter on all fields
  • @Setter on all non-final fields
  • @RequiredArgsConstructor
Also worth knowing
  • @Value: the immutable version of @Data (all fields private final, class final, no setters). This is how Lombok gives an immutable class.
  • @Builder: generates the builder pattern. @Slf4j: gives a log field.
  • With JPA entities, avoid @Data: generated equals/hashCode/toString over lazy relations can trigger extra queries or infinite recursion.
Interview corner
How does Lombok work?

It is an annotation processor that hooks into the compiler and modifies the syntax tree, so the generated methods exist in the .class file but not in the source.

@Data vs @Value?

@Data makes a mutable bean (getters, setters, equals, hashCode, toString); @Value makes an immutable one.

Lombok vs records?

Records are a language feature for immutable data carriers (no dependency, no setters possible). Lombok also covers mutable classes, builders, logging etc.
