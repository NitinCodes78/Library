Annotations

Metadata you attach to code. Tools and frameworks read it with reflection and add logic.

What is an annotation?

Written with @.

  1. It is a kind of adding metadata to the Java code, which we can use at runtime to add certain logic.
  2. This metadata is read using reflection.
Annotations
Pre-defined
Used on annotations (meta-annotations):
@Target, @Retention, @Documented, @Inherited, @Repeatable
Used on Java code (classes, methods, ...):
@Deprecated, @Override, @SuppressWarnings, @FunctionalInterface, @SafeVarargs
Custom / user-defined
@YourName, e.g. @Hello

The 5 built-in annotations used on Java code are provided by Java, other than the ones from Spring, JPA etc.

Annotations used on Java code

@Deprecated

  1. Shows a compile-time warning on usage of deprecated classes or methods.
  2. It means there is no further improvement on this, and a new alternative is present.
  3. Can be used over: constructor, field, local variable, method, package, parameter, type (class, interface, enum).

@SuppressWarnings

@SuppressWarnings("deprecation")     // add it where a deprecated method is called, to suppress the warning
@SuppressWarnings("unused")
@SuppressWarnings("all")

public class Main {
    @SuppressWarnings("deprecation")
    public static void main(String[] args) {
        // calls deprecated stuff
    }
}

You can also use it on top of the class to suppress warnings in all the methods.

Its scope is lexical: suppose main calls B and B calls C. Then it will suppress only for the main method, i.e. only within those curly braces.

@SafeVarargs

  • Used to suppress the "heap pollution" warning.
  • Used over constructors and methods which have variable arguments as parameter.
  • Method should be either static or final (i.e. methods which cannot be overridden).
  • In Java 9, we can use it on private methods too.

Heap pollution

An object of one type (example String) storing the reference of another type of object (example Integer).

List<Integer> list = new ArrayList<>();
list.add(1);  list.add(2);
List ls = list;               // raw (non-generic) list: any change in ls is now reflected in list too

ls.add("Hello");              // but list was of type Integer!

The above code compiles successfully but is an example of heap pollution (and it fails later, when someone reads that element as an Integer).

This does not happen with Integer[] arrays, because arrays check everything at runtime, whereas generics erase their types at runtime (type erasure). List<Integer> is treated just like List at runtime: once we get away from the compiler (fooled it), generics are no help.

Meta annotations

1. @Target

Restricts where to use the annotation when defining a custom annotation.

@Target(ElementType.METHOD)
public @interface Override { }       // @interface is the way to define a custom annotation

@Target({ElementType.CONSTRUCTOR, ElementType.METHOD})
public @interface SafeVarargs { }

@Target(ElementType.ANNOTATION_TYPE) // can be used only on another annotation

2. @Retention

Tells how long the annotation will be stored.

PolicyMeaning
SOURCEDiscarded by the compiler itself; not recorded in the .class file.
CLASSRecorded in the .class file but ignored by the JVM at run time, so no reflection (reflection happens at runtime).
RUNTIMERecorded in the .class file and available during run time, so reflection can be used.
.javacompile.classrunJVM
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.SOURCE)
public @interface Override { }

// Eagle.java                          // Eagle.class
public class Eagle implements Bird {   public class Eagle implements Bird {
    @Override                              // not there in .class
    public void fly() { }                  public void fly() { }
}                                      }
Good to know

If you don't write @Retention, the default is CLASS. Spring and JPA annotations are all RUNTIME, since the framework reads them while your app is running.

3. @Documented

By default, annotations are ignored when Java Documentation is generated (Javadoc is just a tool to generate documentation of your method/class). With this, even annotations will come in the Javadocs. It's put on top of @SafeVarargs, so wherever I use @SafeVarargs, I'll see the annotation in the generated documentation.

4. @Inherited

Only used on a class. By default, annotations applied on a parent class are not available to child classes, but they are after this meta-annotation.

5. @Repeatable

Allows us to use the same annotation more than once at the same place.

@Repeatable(Categories.class)
public @interface Category {
    String name();
}

@Category(name = "Carnivore")
@Category(name = "Bird")
public class Eagle { }                // more than one

// Container: we have to define it
@Retention(RetentionPolicy.RUNTIME)
@interface Categories {
    Category[] value();               // must be named value; creates an array of annotation Category
}

Category[] categoryAnnotationArray =
        new Eagle().getClass().getAnnotationsByType(Category.class);
for (Category can : categoryAnnotationArray) {
    System.out.println(can.name());
}

User-defined (custom) annotations

Using the keyword @interface. The "methods" inside are more like fields:

  • No parameters, no body.
  • Return type is restricted to primitives, Class, String, enums, annotations and arrays of these types.
public @interface MyCustomAnnotation {
    String name();                    // return type; no parameter, no body
}

@MyCustomAnnotation(name = "Testing")
public class Eagle {
    public void fly() { }
}
Putting it together: read a custom annotation 
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
public @interface MyCustomAnnotation {
    String name();
}

MyCustomAnnotation a = Eagle.class.getAnnotation(MyCustomAnnotation.class);
System.out.println(a.name());         // Testing

Without RUNTIME retention, getAnnotation would return null. This is exactly what Spring does with @Component, @Service and friends.

Interview corner
What are the three retention policies?

SOURCE (compiler only), CLASS (in the .class file, not visible at runtime; the default), RUNTIME (visible through reflection).

How do frameworks like Spring use annotations?

They scan classes, read RUNTIME annotations with reflection and act on them: create beans, wire dependencies, expose endpoints.

What is a marker annotation?

An annotation with no elements, such as @Override.

What is a meta-annotation?

An annotation applied to another annotation: @Target, @Retention, @Documented, @Inherited, @Repeatable.
