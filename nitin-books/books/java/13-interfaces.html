Interfaces

Contracts, polymorphism, and how Java gets multiple inheritance without the diamond.

Interface rules

An interface's object can't be created.

  1. Only public and default access modifiers are allowed for a top-level interface (protected and private are not).
  2. It can extend a comma-separated list of parent interfaces. It cannot extend a class. 
    interface A extends B, C { }     // B and C are interfaces
  3. Helps to achieve polymorphism: different classes override and provide different behaviours for the same method, e.g. fly() overridden by say 10 classes.
  4. In Java, multiple inheritance is possible only through interfaces. No diamond problem, because the implementing class has to provide the implementation of all its parents' methods (no clash).
  5. All methods in an interface are implicitly public and abstract. They can't be protected or private (private is allowed from Java 9, see below), and can't be declared final.
  6. Fields in an interface are implicitly public, static and final. Can't make them private or protected: int val = 2000;
  7. Overriding methods in the child should also be public and must override all the methods declared in the interface.
  8. A child abstract class is not forced to provide implementation of all the methods in the interface.

Abstract child class

public interface Bird {
    public void canFly();
    public void noOfLegs();
}

public abstract class Eagle implements Bird {
    @Override
    public void canFly() { }
    public abstract void beakLength();
}
// Eagle's child class has to override noOfLegs() and beakLength()

Nested interface

Declared within another interface (must be public) or within a class (can have any access modifier).

When you implement the outer interface, the inner interface's implementation is not required, and vice versa.

class Eagle implements Bird.NonFlyingBird { }

Bird.NonFlyingBird obj = new Eagle();

Two things to keep in mind: an interface variable is always a public static final constant, whereas an abstract class can hold ordinary instance state. And since Java 8 an interface can carry implementation via default/static methods, which the next sections cover.

When to pick which

Use an interface for a capability or contract that unrelated classes can share (Comparable, Runnable). Use an abstract class for a family of closely related classes that share state and common code.

Default methods (Java 8 onwards)

Before Java 8, an interface could have only abstract methods, and every child class had to provide implementations.

The drawback: suppose I have to add a new method to an interface. Then all its children have to provide its implementation, and all existing code breaks.

public interface Bird {
    public void canFly();

    default int methA() {      // just with default, we are able to provide implementation
        return 100;
    }
}

default is not an access modifier; it is a different concept. The method is public by default. Now all its children can use methA, and none of them breaks.

We can't have default static int methA(). They are contradictory: static belongs to the interface itself, whereas default provides a concrete implementation for instances of the classes that implement the interface.

The diamond problem comes back

An interface can extend multiple interfaces. If two parent interfaces have a default method with the same name, then the child has to provide its implementation. This is the solution. Three ways to handle default methods when inheriting:

public interface A {
    default boolean canBreathe() { return true; }
}

// 1st way: just inherit (works fine)
public interface B extends A { }
class C implements B { }
C obj = new C();
obj.canBreathe();                      // ✓

// 2nd way: re-declare it as abstract
public interface B extends A {
    boolean canBreathe();              // it has now become abstract
}
class C implements B {
    public boolean canBreathe() {      // has to provide implementation
        return true;
    }
}

// 3rd way: provide an overriding implementation
public interface Bird extends LivingThing {
    default boolean canBreathe() {
        boolean canBreatheOrNot = LivingThing.super.canBreathe();
        // do something else
        return canBreatheOrNot;
    }
}
Good to know: the two-parents clash

When a class implements two interfaces that both have the same default method, the compiler forces you to override it. Inside you can pick one explicitly: InterfaceA.super.method();. A class method always wins over an interface default.

Static methods in an interface (Java 8)

  1. It can provide the implementation of the method in the interface.
  2. But it can't be overridden by classes which implement the interface.
  3. We access it using the interface name itself: Bird.helper().
  4. It's public by default.

A child can create the same method, but it will belong to that child class only (it's not overridden, so don't use @Override).

Default methods can be overridden, but not static.

Private methods in an interface (Java 9)

  • We can provide the implementation of a method, but with the private access modifier.
  • Cannot be accessed outside this interface; not inherited by child classes or sub-interfaces.
  • Brings more readability: if multiple default methods share some code, this can help.
  • Cannot be abstract, so it must have a body.
default int addEven(int... nums) {
    return sumDigits(nums);
}

private int sumDigits(int... nums) {     // helper method
    // ...
}

We know in Java, a static method only calls static members (variables/methods), while a non-static method can access both. A similar rule applies here:

  • From a static interface method, we can only call a private static interface method.
  • A private static interface method can be called from both static and non-static methods.
Interview corner
Why were default methods added in Java 8?

To evolve interfaces (like adding forEach to Iterable) without breaking every existing implementation.

How does Java avoid the diamond problem?

Classes get one parent class only. For interfaces with clashing defaults, the compiler forces you to override and choose explicitly.

Can an interface have a constructor? Why not?

No. It holds no instance state to initialise and cannot be instantiated.

What is a marker interface?

An interface with no methods, like Serializable or Cloneable, used to tag a class with a capability.
