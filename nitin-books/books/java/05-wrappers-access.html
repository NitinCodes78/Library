Autoboxing and unboxing

Autoboxing

primitive → wrapper

int a = 10;
Integer a1 = a;

Unboxing

reference → primitive

Integer x = 20;
int x1 = x;

Java does both automatically, so list.add(10) works on a List<Integer>:

List<Integer> list = new ArrayList<>();
list.add(10);        // 10 is a primitive, boxed automatically

Why wrapper classes exist

  1. Primitives vs references. A local primitive lives on the stack, whereas objects live in the heap (a primitive field of an object lives inside that object, on the heap). Java always passes arguments by value: a primitive is copied, a reference is copied too, but both copies point to the same object, so a change made through it is seen by the caller. If I want a change to be reflected after the call, I need a mutable reference type (note that wrapper classes like Integer are themselves immutable, so void f(Integer x) { x = 10; } will not change the caller either; use your own class, an array or AtomicInteger). 
    int a = 5;
void f(int x) { x = 10; }
f(a);                  // a remains 5 only

class X { int a = 5; }
void f(X x) { x.a = 10; }   // it changes the object (reflected everywhere)
    This is the advantage of a non-primitive data type: flexible memory management.
  2. Collections. They all work on reference data types (objects). They are built around OOPs, store and manage instances of classes, and generics work with objects.
  3. Null. Reference types can be null.

final

final makes a variable's value constant.

static final int EMP_ID = 10;     // CONSTANT

Also: final methods cannot be overridden. Because it can't be changed, then why override.

Interview corner
What is autoboxing? Any danger?

Automatic conversion between a primitive and its wrapper. Danger: unboxing a null wrapper throws NullPointerException, and boxing inside big loops creates many objects.

Integer a = 127, b = 127; a == b? And 128?

For 127 it is true (small values −128 to 127 are cached), for 128 it is false. Use equals() to compare wrappers.

Why can't a List hold int?

Generics work only with reference types. List<int> is not allowed, so we use List<Integer> and autoboxing.

Difference between default and protected?

Default is package-only. Protected is package plus subclasses in other packages.
