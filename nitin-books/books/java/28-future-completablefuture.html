Future, Callable and CompletableFuture

Getting results back from async work, and chaining it.

The problem

ThreadPoolExecutor poolExecutor = new ThreadPoolExecutor(1, 1, 1, TimeUnit.HOURS,
        new ArrayBlockingQueue<>(1), Executors.defaultThreadFactory(),
        new ThreadPoolExecutor.AbortPolicy());

// a new thread will be created and it will perform the task
poolExecutor.submit(() -> {
    System.out.println("this is the task, which thread will execute");
});
// main thread will continue processing, it won't wait for the pool executor's thread to complete

Its return type is Future. Now what if the caller (main, in this case) wants to know the status of the task: whether it completed or failed? It is running in async mode, the pool executor does it.

Future

An interface which represents the result of the async task. It allows you to check if: (i) the computation is complete, (ii) get the result, (iii) take care of the exception, if any.

Future<?> futureObj = poolExecutor.submit(() -> {
    System.out.println("this is the task, which thread will execute");
});
// status of the task which the caller created:
System.out.println(futureObj.isDone());
MethodWhat it does
boolean cancel(boolean mayInterrupt)Attempts to cancel the execution of the task. Returns false if the task can't be cancelled (typically because the task already completed); returns true otherwise.
boolean isCancelled()Returns true if the task was cancelled before it completed.
boolean isDone()Returns true if the task completed. Completion may be due to normal termination, an exception or cancellation: in all of these cases this method returns true.
V get()Waits, if required, for the completion of the task (the main thread blocks). After the task completes, it retrieves the result if available. I.e. the current thread will pause (block) and wait until the computation is finished.
V get(long timeout, TimeUnit unit)Waits for at most the given timeout period. Throws TimeoutException if the timeout period finished and the task is not yet completed.

Three flavours of submit()

submit(Runnable)
submit(Runnable, T)
submit(Callable<T>)
Runnable
@FunctionalInterface
public interface Runnable { public abstract void run(); }
Callable<V>
@FunctionalInterface
public interface Callable<V> { V call() throws Exception; }

Callable

  • Callable represents the task which needs to be executed, just like Runnable.
  • But the difference: Runnable does not have any return type; Callable has the capability to return a value (and it may throw a checked exception).
// Callable: returns 45
Future<Integer> fo = poolExecutor.submit(() -> {
    System.out.println("something");
    return 45;
});

// vs Runnable: nothing returned
Future<?> fo = poolExecutor.submit(() -> {
    System.out.println("something");
});
Object obj = fo.get();      // it will be null (nothing returned)

2nd way: submit(Runnable task, T result)

List<Integer> output = new ArrayList<>();
Future<List<Integer>> fo = poolExecutor.submit(() -> {
    output.add(100);
    System.out.println("Task2 with Runnable & return object");
}, output);                         // the result returned once the task completes

try {
    List<Integer> outputFromFo = fo.get();
    System.out.println(outputFromFo.get(0));
} catch (Exception e) { }

The above is a sort of workaround to return something, but Callable is cleaner:

Future<List<Integer>> fo = poolExecutor.submit(() -> {      // Callable
    List<Integer> output = new ArrayList<>();
    output.add(300);
    return output;
});
Good to know

When a task throws, get() wraps it in an ExecutionException (the real cause is getCause()). Future's weakness: get() blocks and you cannot chain steps. That is why CompletableFuture exists.

CompletableFuture

Introduced in Java 8 to help in async programming. We can consider it as an advanced version of Future, which provides additional capabilities like chaining. (It is a class that implements the interface Future.)

1. supplyAsync

public static <T> CompletableFuture<T> supplyAsync(Supplier<T> supplier)
public static <T> CompletableFuture<T> supplyAsync(Supplier<T> supplier, Executor executor)
  • The supplyAsync method initiates an async operation.
  • The supplier is executed asynchronously in a separate thread.
  • If we want more control on threads, we can pass an Executor in the method.
  • By default it uses the shared ForkJoinPool executor (the common pool), which dynamically adjusts its pool size based on processors.

Supplier is defined in Java as:

@FunctionalInterface
public interface Supplier<T> {
    T get();
}
ThreadPoolExecutor poolExecutor = new ThreadPoolExecutor(/* ... */);

CompletableFuture<String> asyncTask1 = CompletableFuture.supplyAsync(() -> {
    return "task completed";
}, poolExecutor);

System.out.println(asyncTask1.get());

2. thenApply and thenApplyAsync

  • Apply a function to the result of the previous async computation.
  • Returns a new CompletableFuture object.
CompletableFuture<String> asyncTask1 = CompletableFuture.supplyAsync(() -> {
    // task which a thread needs to execute
    return "Concept and ";
}, poolExecutor).thenApply((String val) -> {
    // functionality which can work on the result of the previous async task
    return val + "Coding";
});
thenApplythenApplyAsync
Synchronous execution: uses the same thread which completed the previous async task.Asynchronous execution: uses a different thread (from the fork-join pool if we do not provide the executor in the method call) to complete this function.
If multiple thenApplyAsync are used, ordering can't be guaranteed: they will run concurrently.

3. thenCompose and thenComposeAsync

  • Chain together dependent async operations.
  • When the next async operation depends on the result of the previous result, we can tie them together.
  • For async tasks, we can bring some ordering using this (i.e. the previous async must finish first).
  • thenCompose: same thread. thenComposeAsync: different thread, but ordering is kept.
CompletableFuture<String> user  = CompletableFuture.supplyAsync(() -> "user-42");
CompletableFuture<String> order = user.thenCompose(id -> CompletableFuture.supplyAsync(() -> "orders of " + id));
thenApply vs thenCompose

It is the map vs flatMap idea. If your function itself returns a CompletableFuture, use thenCompose; otherwise you get a nested CompletableFuture<CompletableFuture<T>>.

4. thenAccept and thenAcceptAsync

  • Generally the end stage in the chain of async operations.
  • It does not return anything (CompletableFuture<Void>).
  • thenAccept: same thread; thenAcceptAsync: new thread.
CompletableFuture<Void> asyncTask1 = CompletableFuture.supplyAsync(() -> {
    return "Concept &";
}, poolExecutor)
.thenAccept((String val) -> System.out.println("All stages completed"));

5. thenCombine and thenCombineAsync

Used to combine the results of 2 independent CompletableFutures. (thenCombine: synchronous / same thread; thenCombineAsync: new thread.)

CompletableFuture<Integer> asyncTask1 = CompletableFuture.supplyAsync(() -> {
    return 10;
}, poolExecutor);

CompletableFuture<String> asyncTask2 = CompletableFuture.supplyAsync(() -> {
    return "K";
}, poolExecutor);

CompletableFuture<String> combinedFutureObj = asyncTask1.thenCombine(asyncTask2,
        (Integer val1, String val2) -> val1 + val2);       // "10K"

Also worth knowing

CompletableFuture.allOf(...) waits for all, anyOf(...) for the first. Error handling: exceptionally(ex -> fallback) and handle((res, ex) -> ...). Without an Executor argument, async tasks run on daemon threads of the common pool, so a short-lived main can exit before they finish.

Interview corner
Runnable vs Callable?

Runnable returns nothing and cannot throw checked exceptions; Callable returns a value and may throw.

Future vs CompletableFuture?

Future can only poll or block on get(). CompletableFuture adds non-blocking chaining, combining, and error handling.

thenApply vs thenApplyAsync?

thenApply runs on the thread that completed the previous stage; the Async version hands the step to another thread (pool).

thenApply vs thenCompose?

map vs flatMap: use thenCompose when the next step itself returns a CompletableFuture.

Which pool does supplyAsync use by default?

ForkJoinPool.commonPool(); pass your own Executor for control.
