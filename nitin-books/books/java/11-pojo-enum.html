POJO, Enum and Final Classes

Three special kinds of class you will meet constantly.

POJO class

Plain Old Java Object.

  1. Contains variables and their getter and setter methods.
  2. Class should be public, with a default public constructor.
  3. No annotations like @Table, @Entity, @Id etc. should be used.
  4. Should not extend any class or implement any interface.
Good to know

These are the strict textbook rules. In day-to-day work, people also call a simple data class with a few annotations a "POJO" (and call a JPA entity a "bean"). In interviews, give the strict definition first.

Enum class

  1. Holds a collection of CONSTANTS (variables whose values cannot be changed).
  2. Constants are static and final implicitly (we don't have to write it).
  3. It cannot extend any class, as it internally extends java.lang.Enum.
  4. It can implement interfaces.
  5. It can have variables, constructors, methods.
  6. It cannot be instantiated with new: its constructor is always private (even if you don't write it, bytecode makes it private).
  7. No other class can extend an enum class.
  8. It can have abstract methods, and all the constants must implement that abstract method.

In Java, even if one method is abstract, the class has to be abstract too, but the enum above is the exception.

Enum with an abstract method

public enum Operation {
    ADD {
        @Override
        public int apply(int a, int b) { return a + b; }
    },
    SUBTRACT {
        @Override
        public int apply(int a, int b) { return a - b; }
    };

    public abstract int apply(int a, int b);   // not possible in a normal non-abstract class
}

Operation opAdd = Operation.ADD;      // reference to the single, pre-initialized ADD instance
int result = opAdd.apply(5, 3);

ADD is an object. In Java, every enum constant is a singleton object of its enum type. Loop over them like this:

for (Operation op : Operation.values()) {
    System.out.println(op.name());
}

Built-in methods

public enum EnumSample {
    MONDAY,      // 0
    TUESDAY,     // 1
    WEDNESDAY,   // 2
    THURSDAY,    // 3
    FRIDAY,      // 4
    SATURDAY,    // 5
    SUNDAY;      // 6
}

Internally they are assigned values starting from zero.

MethodWhat it does
values()returns an array of all the constants
ordinal()the number assigned to it: 0, 1, 2 ...
valueOf("FRIDAY")gets the constant from its text
name()the constant's text
for (EnumSample sample : EnumSample.values()) {
    System.out.println(sample.ordinal());   // 0, 1, 2 ...
}

EnumSample enumVariable = EnumSample.valueOf("FRIDAY");
System.out.println(enumVariable.name());    // FRIDAY

These must be static internally: we access them without an object.

Good to know

valueOf() throws IllegalArgumentException if the text matches no constant. Avoid relying on ordinal() for storing in a database, because reordering the constants silently changes the numbers. Store name() instead (that is what @Enumerated(EnumType.STRING) does in JPA).

Enum with fields and a constructor

public enum EnumSample {
    MONDAY(101, "1st day of the week"),
    TUESDAY(102, "2nd day of the week");

    private int val;
    private String comment;

    // always private; only used inside the class to initialise
    // the constants (MONDAY, TUESDAY)
    EnumSample(int val, String comment) {
        this.val = val;
        this.comment = comment;
    }

    // getters and setters: one set per constant, works for all constants
    public int getVal() { return val; }
    public String getComment() { return comment; }

    public static EnumSample getEnumFromValue(int value) {
        for (EnumSample sample : EnumSample.values()) {
            if (sample.val == value) {
                return sample;
            }
        }
        return null;
    }
}

String str = EnumSample.getEnumFromValue(101).getComment();   // static method, then getter

Method override by a constant

A single constant can override a method on its own:

public enum EnumSample {
    MONDAY {
        @Override
        public void dummyMethod() {
            System.out.println("-- Monday only --");
        }
    },
    TUESDAY,
    WEDNESDAY;

    public void dummyMethod() {
        System.out.println("-- default --");
    }
}

Enum implementing an interface

public interface MyInterface {
    public String toLowerCase();
}

public enum EnumSample implements MyInterface {
    MONDAY, TUESDAY;

    @Override
    public String toLowerCase() {
        return name().toLowerCase();
    }
}

Final class

A class declared final cannot be inherited. Examples: String, all the wrapper classes.

public final class Constants { }
public class Other extends Constants { }   // ✗ compile error
Interview corner
Why is an enum a good singleton and a good constant holder?

The JVM creates each constant exactly once and guarantees it. Constants are type-safe, can carry data and behaviour, and work in switch.

Can an enum extend a class?

No, it already extends java.lang.Enum. It can implement interfaces.

Can you call new on an enum?

No, the constructor is implicitly private.

Name the final classes you know.

String, Integer and the other wrappers, Math.
