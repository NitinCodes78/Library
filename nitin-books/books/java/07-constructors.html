Constructors

How an object comes to life, what Java adds for free, and how constructors call each other.

What a constructor is

  • Used to create / initialize an instance.
  • Its name is the same as the class name.
  • It has no return type.
  • It can't be static, final, abstract or synchronized.
  • It can't be overridden.
Employee obj = new Employee();    // `new` lets us call the constructor
Constructor or method? 
class Employee {
    Employee() { }              // constructor (same name as class, no return type)

    int Employee() {            // a METHOD: it has a return type,
        return 10;              // even though the name matches the class
    }
}

Two rules explained

  1. If a constructor were static, it could not access non-static variables, so it could not initialize them. So a constructor can't be static.
  2. Interfaces can't have constructors, because we can't make their objects.

The default constructor

public class Calculation {
    String name;
}

Java gives this class a default constructor. It sets name to null and the other variables to their default values too.

If we manually define any constructor, no default constructor is added.

Calculation(String a) {
    this.name = a;
}

Calculation c1 = new Calculation();         // ✗ error: a constructor with an argument is defined
Calculation c2 = new Calculation("cat");    // ✓

Private constructor

A private constructor can't be instantiated from outside. It is used in the Singleton pattern.

public class Calculation {
    private static Calculation instance;

    private Calculation() { }


    public static synchronized Calculation getInstance() {
        if (instance == null) {
            instance = new Calculation();   // created only once
        }
        return instance;                    // same object every time
    }
}

Calculation c1 = new Calculation();           // ✗ private constructor
Calculation obj = Calculation.getInstance();  // ✓

Other ways to get a singleton: eager initialization with private static final Calculation INSTANCE = new Calculation();, or an enum singleton. Only one object can be created this way.

Constructor chaining with this()

this(...) calls another constructor of the same class.

public class Calculation {
    String name;
    int empID;

    Calculation() {
        this(10);                    // → calls Calculation(int)
    }
    Calculation(int empID) {
        this("sj", empID);           // → calls Calculation(String, int)
    }
    Calculation(String name, int empID) {
        this.name = name;
        this.empID = empID;
    }
}

Rule worth remembering: this(...) (and super(...)) must be the first statement in a constructor.

Constructor chaining with super()

class Person {
    Person() { System.out.println("Person"); }
}
class Manager extends Person {
    Manager() { System.out.println("Manager"); }
}

new Manager();     // prints: Person, then Manager

Creating a Manager prints Person first, then Manager. It goes from top to bottom. This is because there is a hidden super() as the first line of the Manager constructor. Java adds it by default.

Objectsuper()Personsuper()Manager

Java calls super() automatically only for no-arg constructors. So if Person has only:

Person(int empID) { }

then in Manager we have to explicitly call super(empID) for this constructor to be invoked. Otherwise it will not compile.

Interview corner
Can a constructor be private? Why would you?

Yes. It blocks new from outside the class. Used for Singletons, utility classes and factory methods.

Does Java always give a default constructor?

No, only when you write no constructor at all. Write any constructor and the default disappears.

Can constructors be inherited or overridden?

Neither. A child's constructor can call the parent's with super(), but constructors are not inherited.

Can you call this() and super() in the same constructor?

No. Both must be the first statement, so you can only use one.

What is the order of construction in inheritance?

Parent constructor runs first, then child.
