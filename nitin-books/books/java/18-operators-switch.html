Bitwise NOT ~

Changes 1 to 0 and 0 to 1. ~a for a = 4 (0100) becomes 1011.

The leftmost bit is the Most Significant Bit (MSB), used as the sign bit; the rightmost is the Least Significant Bit (LSB). When the number is positive the MSB is 0, and it is 1 when the number is negative.

It can be calculated with the formula: ~n = -(n + 1).

How can we confirm -5 is 1011?

  1. Take the positive bits of 5, i.e. 0101.
  2. Then find its 2's complement.
  3. 1st complement = 1010 (reverse all its bits).
  4. 2nd complement = 1010 + 1 = 1011 (MSB is 1).

Bitwise shift operators

OperatorName
<<signed left shift
>>signed right shift
>>>unsigned right shift

There is no <<< (unsigned left shift), as << and <<< would be equal.

a = 4 i.e. 00100

  • a << 1: every bit moves left by one, the leftmost bit is discarded, the LSB becomes empty and is filled by zero: 01000 (8).
  • a << 2: 10000 (16), the new empty places filled with zero.
  • a >> 1: every bit moves right; the empty MSB position gets filled by what was there earlier (the sign bit). It was 0, so 00010 (2).

Suppose a = -5 i.e. 1011:

  • a >> 1: the empty MSB gets filled by what was there earlier, that is 1: 1101.
  • a >>> 1: in unsigned right shift, the MSB position is always filled with zero regardless of what was there earlier: 0101 (in this 4-bit picture).
  1. Shifting left by n bits multiplies a number by 2n, faster than Math.pow(2, n).
  2. Right shifting by n bits divides by 2n.
  • The 4-bit pictures are for learning. A real Java int has 32 bits, so -5 >>> 1 is 2147483645.
  • Right shift of a negative odd number rounds toward negative infinity: -5 >> 1 = -3 (1101 in 4 bits).
  • Left shift can overflow: 1 << 31 is negative. The shift amount is taken modulo 32 for int (1 << 33 equals 1 << 1).

Switch statements

int a = 1, b = 2;
switch (a + b) {
    case 1:
        System.out.println("...");
        break;                 // break is necessary, else all the cases get executed (fall-through)
    case 2:
        // ...
        break;
    default:                   // default can come here also
        // ...
        break;                 // compulsory if default is not last
    case 3:
        // this gets executed: a + b = 3
}

Cases can be combined, to run the same code:

case 1: case 2: case 3:        // old style, stacked
    // ...
case 1, 2, 3 ->                // Java 14+, same thing, cleaner

Rules

  1. Supported data types for switch: int, short, byte, char or the wrapper classes of them (Integer, Short, Byte, Character), plus enum and String.
  2. The data type in switch and the cases should be the same (a String switch can't have case 1).
  3. return is not possible within a switch that produces a value (see below).
  4. The alternative is the arrow form case N ->.
String day = "";
int val = 1;
String outputVal = switch (val) {
    case 1 -> "One";
    case 2 -> "Two";
    case 3 -> "None";
};     // the result gets assigned; we cannot write some other logic here, just return a value

We use yield to counter this issue, when a case needs more logic:

String outputVal = switch (val) {
    case 1 -> {
        // some logic
        yield "One";
    }
    default -> "Other";
};

A return is allowed inside a classic switch statement (it just exits the method). It is the new switch expression, the one that produces a value, where return, break and continue can't jump out. A switch expression must also be exhaustive: cover every case, or add a default (enums can skip it if all constants are listed).

Interview corner
== vs equals? & vs && ?

&& short-circuits (stops when the left side is false); & always evaluates both sides.

Fast ways to check even/odd or multiply by 8?

(n & 1) == 0 means even; n << 3 is n * 8.

Difference between >> and >>>?

>> keeps the sign (fills with the sign bit); >>> always fills zeros, so a negative number becomes a big positive.

What if you forget break in a switch?

Execution falls through into the next cases until a break or the end.
