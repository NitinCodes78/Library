Collections Framework: Overview, Queue and Deque

One architecture for managing groups of objects: add, update, delete, search.

What is the Collections Framework?

A group of objects (package java.util). The framework provides us the architecture to manage the group of objects, i.e. add, update, delete, search etc.

Why was it needed? Prior to JCF, we had Array, Vector, Hashtable. The problem was that there was no common interface, so it was difficult to remember the methods for each.

Legend: interfaces are the abstract boxes (Iterable, Collection, List, Queue, Deque, Set, SortedSet, NavigableSet, Map, SortedMap); the rest are concrete classes. LinkedList implements both List and Deque.

Iterable and Iterator

Iterable is used to traverse the collection. Its iterator() returns an Iterator object, which provides these methods:

MethodDoes
hasNext()returns true if there are more elements in the collection
next()returns the next element in the collection
remove()removes the last element returned by the iterator
List<Integer> values = new ArrayList<>(Arrays.asList(1, 2, 3));

// (i) explicit iterator
Iterator<Integer> valuesIterator = values.iterator();
while (valuesIterator.hasNext()) {
    int val = valuesIterator.next();
    System.out.println(val);
    if (val == 3) valuesIterator.remove();
}

// (ii) for-each
for (int val : values) { System.out.println(val); }

// (iii) forEach with a lambda
values.forEach((Integer val) -> System.out.println(val));

Whoever implements Iterable, Java allows to iterate in these ways.

Good to know

Removing from a list inside a for-each loop with values.remove(...) throws ConcurrentModificationException. Use iterator.remove() (as above) or removeIf().

Collection vs Collections

  • Collection is part of the Java collection framework. It's an interface that exposes various methods, implemented by the various collection classes like ArrayList, Stack, LinkedList etc.
  • Collections is a utility class and provides static methods like swapping, searching, reverse, copy etc.
Collections.sort(list);
Collections.min(values);

Queue

An interface, child of the Collection interface. Generally follows FIFO (first in, first out), but there are exceptions like PriorityQueue. Supports all methods in Collection plus some other methods:

Pattern to remember: add / remove / element throw; offer / poll / peek return a special value (false / null).

PriorityQueue

Implements Queue. It is based on a priority heap (min and max heap). Elements are stored according to natural ordering (by default) or by a Comparator provided during queue construction time.

PriorityQueue<Integer> minPQ = new PriorityQueue<>();     // for Integer it's ascending, i.e. min heap

PriorityQueue<Integer> maxPQ = new PriorityQueue<>(Comparator.reverseOrder());
// now it behaves like a max heap
OperationComplexity
add & offerO(log n): heapify
poll & removeO(log n): heapify
peekO(1)
remove an arbitrary elementO(n): iterate to find the element

Prefer Comparator.reverseOrder() or (a, b) -> Integer.compare(b, a) for a max heap: the subtraction trick b - a can overflow for large or mixed-sign values and give a wrong order. Also remember that a PriorityQueue's iteration or printing order is not sorted; only poll() gives you elements in priority order.

Deque

Stands for double ended queue: addition and removal from both sides of the queue. It helps to implement both Stack (LIFO) and Queue (FIFO), i.e. it achieves the functionality of both. It has some additional methods than Queue.

Throw exceptionDo not throw exception
addFirst(e)offerFirst(e)
removeFirst()pollFirst()
getFirst()peekFirst()
addLast(e)offerLast(e)
removeLast()pollLast()
getLast()peekLast()

push() and pop() methods are also available to behave as a stack. It's faster for single-threaded use, and recommended for stack and queue DSA problems.

ArrayDeque

A concrete class which implements the methods available in the Queue and Deque interfaces.

ArrayDeque<Integer> ad = new ArrayDeque<>();
ad.push(1);  ad.push(2);
ad.pop();                 // 2 (LIFO, like a stack)
ad.offer(3);  ad.poll();  // FIFO, like a queue

Time complexity

  • Insertion: amortized (most of the time, or on average) O(1), except a few cases like O(n): when the queue size threshold is reached and, to insert an element, its values are copied to a new, bigger array.
  • Deletion: O(1).
  • Access at the ends: O(1): getFirst, getLast etc.
  • Search for an arbitrary value (contains()): O(n).

PriorityQueue and ArrayDeque are not thread-safe. They don't allow null elements. Their thread-safe versions are PriorityBlockingQueue and ConcurrentLinkedDeque:

PriorityBlockingQueue<Integer> pq = new PriorityBlockingQueue<>();
ConcurrentLinkedDeque<Integer> ab = new ConcurrentLinkedDeque<>();
Interview corner
Collection vs Collections?

Collection is the root interface for List, Set and Queue. Collections is a utility class with static helpers (sort, reverse, min, max, unmodifiableList).

poll() vs remove() on a Queue?

Both take the head. On an empty queue poll() returns null; remove() throws NoSuchElementException.

Why prefer ArrayDeque over Stack?

Stack is an old Vector child with synchronised methods (slow). ArrayDeque is faster and has a cleaner API.

Is Map part of the Collection hierarchy?

No. Map is a separate interface hierarchy because it stores key-value pairs.

How do you make a max-heap PriorityQueue?

Pass Comparator.reverseOrder() to the constructor.
