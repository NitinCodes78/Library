Reflection

Looking at classes, methods and fields while the program is running, and even changing them.

What is reflection?

Part of the java.lang.reflect package. It is used to examine classes, methods, fields and interfaces at runtime, and it is also possible to change the behaviour of the class. For example:

  • What all methods are present in the class
  • What all fields are present in the class
  • What is the return type of a method
  • What is the modifier of the class
  • What all interfaces the class has implemented
  • Change the value of its public and private fields

The Class class

To do reflection, we first need an object of the class Class. Its instance represents classes during runtime. The JVM creates one Class object for each and every class which is loaded during runtime. It holds metadata about that class: its methods, fields, constructors and so on.

Three ways to get a Class object

// assume we have: class Bird { }

// (i) using forName() method
Class birdClass = Class.forName("Bird");

// (ii) using .class
Class birdClass = Bird.class;

// (iii) using getClass() method: first get the object
Bird birdObj = new Bird();
Class birdClass = birdObj.getClass();

Reflection of classes

public class Eagle {
    public String breed;
    private boolean canSwim;
    public void fly() { System.out.println("fly"); }
    public void eat() { }
}

Class eagleClass = Eagle.class;
eagleClass.getName();                                        // Eagle
Modifier.toString(eagleClass.getModifiers());                // public

Getting methods

CallReturns
getMethods()all public methods, including the ones inherited from Object (wait(), notify() ...)
getDeclaredMethods()all public and private methods of this class only, not Object's
Method[] methods = eagleClass.getMethods();
for (Method method : methods) {
    method.getName();               // fly
    method.getReturnType();         // void
    method.getDeclaringClass();     // Eagle
}

Method[] methods = eagleClass.getDeclaredMethods();

Invoking methods of a class

Class eagleClass = Class.forName("Eagle");
Object eagleObject = eagleClass.getDeclaredConstructor().newInstance();   // it's an object

Method flyMethod = eagleClass.getMethod("fly", int.class, String.class);
//                                        name   comma separated parameter types

flyMethod.invoke(eagleObject, 2, "Hello");     // will execute the fly method with int and String arguments

Class.newInstance() is deprecated since Java 9, so use getDeclaredConstructor().newInstance() as above. For the example to run, the class must declare fly(int, String) with those parameter types.

Reflection of fields

Class eagleClass = Eagle.class;
Field[] fields = eagleClass.getFields();            // public fields only
// loop over and call field.getName(), field.getType() ...   → breed, String

Field[] fields = eagleClass.getDeclaredFields();    // both public and private fields

Setting the value of a public field

Class eagleClass = Eagle.class;
Eagle eagleObj = new Eagle();
Field field = eagleClass.getDeclaredField("breed");   // we extracted the field
field.set(eagleObj, "BrownBreed");                    // which object, and what value to set
System.out.println(eagleObj.breed);

The above throws an exception for a private field. To change a private field, just add one line:

field.setAccessible(true);

That's a disadvantage of reflection: it bypasses encapsulation, since it lets you access private fields outside the class.

Reflection of constructors

Through this, reflection also breaks the Singleton pattern.

public class Eagle {
    private Eagle() { }          // private constructor
}

Class eagleClass = Eagle.class;
Constructor[] eagleConsList = eagleClass.getDeclaredConstructors();   // loop over it

for (Constructor eagleConstructor : eagleConsList) {
    eagleConstructor.setAccessible(true);
    Eagle eobj = (Eagle) eagleConstructor.newInstance();   // object instantiated, though the constructor is private
}

Why not use reflection?

  1. Breaks encapsulation and the singleton pattern.
  2. It's slow, because it happens at runtime.
Good to know

Reflection is what frameworks are built on. Spring finds your @Component classes, creates them and injects dependencies; Hibernate fills entity fields; Jackson maps JSON to fields; JUnit finds @Test methods. All through reflection. Also, since Java 9 the module system can block setAccessible(true) on JDK internals (InaccessibleObjectException).

Interview corner
getMethods() vs getDeclaredMethods()?

getMethods(): public methods, including inherited. getDeclaredMethods(): every method declared in this class (any access), but not inherited ones.

How can reflection break a singleton and how do you stop it?

By calling the private constructor after setAccessible(true). Stop it by throwing from the constructor if an instance exists, or use an enum singleton.

Where is reflection used in Spring Boot?

Bean creation, dependency injection, annotation scanning, and proxies for AOP and @Transactional.
