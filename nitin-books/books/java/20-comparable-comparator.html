Comparable vs Comparator

How Java knows which object comes first when you sort.

Both provide a way to sort a collection of objects. They don't sort themselves, they just help: they tell the sorting algorithm how to compare two objects.

The problem: sorting objects

public class Car {
    String carName;
    String carType;
    Car(String name, String carType) {
        this.carName = name;
        this.carType = carType;
    }
}

Car[] carArray = new Car[3];
carArray[0] = new Car("SUV", "petrol");
carArray[1] = new Car("Sedan", "diesel");
carArray[2] = new Car("HatchBack", "CNG");
Arrays.sort(carArray);

This throws: java.lang.ClassCastException: Car cannot be cast to java.lang.Comparable. It's not something as clear as an Integer array, where Java knows the order, so it throws the above exception.

There are two ways to teach Java how to sort the object array.

1. Comparator (a functional interface)

Abstract method: int compare(T obj1, T obj2). The sorting algorithm uses this compare method to compare two variables and decide whether to swap them or not.

ReturnsMeaning
positive (e.g. 1)v1 is bigger than v2
0v1 and v2 are equal
negative (e.g. -1)v1 is smaller than v2

(Here v1 and v2 are obj1 and obj2.) Mostly in the algorithm, if the method returns a positive value, it swaps the values, so the smaller comes first in ascending order.

Walkthrough

Integer a[] = {6, 4, 1, 9, 2, 11};
Arrays.sort(a, (Integer val1, Integer val2) -> val1 - val2);
//             ^ compare method being overridden: providing its implementation
//               a lambda way to initialize the Comparator functional interface
v1 = 6, v2 = 9
6 - 9 = -3 < 0
no swap
v1 = 9, v2 = 6
9 - 6 = 3 > 0
swap: 6 comes before 9

So it just provides a way to compare two values, and the sort performs the swap based on that. Internally Arrays.sort may use any algorithm; we don't care. It does not sort itself, it just compares.

If I do val2 - val1, it will be descending order: v1 = 6, v2 = 9, i.e. 9 - 6 > 0, so swap.

Subtracting to compare is only a teaching shortcut: Integer.MAX_VALUE - (-1) overflows and flips the sign. In real code prefer Integer.compare(val1, val2) or, for descending, Integer.compare(val2, val1).

For the Car array

Arrays.sort(carArray, (Car obj1, Car obj2) ->
        obj2.carType.compareTo(obj1.carType));      // comparator (descending by type)

Instead of a lambda, we could write a class:

public class CarNameComparator implements Comparator<Car> {   // functional interface, generic
    @Override
    public int compare(Car o1, Car o2) {
        return o2.carName.compareTo(o1.carName);
    }
}

Arrays.sort(carArray, new CarNameComparator());
// for a list, use:
Collections.sort(cars, new CarNameComparator());

Or the class could implement the comparator itself:

public class Car implements Comparator<Car> {
    String carName, carType;
    @Override
    public int compare(Car o1, Car o2) {
        return o1.carName.compareTo(o2.carName);
    }
}
Collections.sort(cars, new Car());       // inside it the compare method will be used
Good to know

That last style works, but it's an odd design (a car that compares other cars). A separate comparator class, or a lambda, is cleaner. Modern style: cars.sort(Comparator.comparing(c -> c.carName)), and chain with .thenComparing(...) or flip it with .reversed().

2. Comparable

Abstract method: int compareTo(T obj2). It's an interface, they have not defined it as a functional interface, but it has one abstract method compareTo. (We saw that it's not necessary to add @FunctionalInterface, but if added, it can't have more than one abstract method.)

Here only one parameter is accepted (the other object is this). In Comparator we could use a lambda expression or a new class like CarNameComparator. But here, since only one parameter is accepted, we have only one option left, i.e. public class Car implements Comparable<Car> and compare using this.compareTo.

Arrays.sort(new Integer[]{4, 2, 7, 6});      // internally it uses compareTo

In Java it's defined like this, inside the Integer class:

public int compareTo(Integer anotherInteger) {
    return compare(this.value, anotherInteger.value);
}

public static int compare(int x, int y) {
    return (x < y) ? -1 : ((x == y) ? 0 : 1);     // as we can see, it's ascending
}

In Java, internally Integer extends Number implements Comparable<Integer>. So for Integer we can't perform a descending sort using Comparable, because the compareTo method is already defined; for descending we'll have to use a Comparator.

For a custom class

public class Car implements Comparable<Car> {
    String carName;
    String carType;
    Car(String name, String type) {
        this.carName = name;
        this.carType = type;
    }

    @Override
    public int compareTo(Car o2) {
        return this.carType.compareTo(o2.carType);
    }
}

List<Car> carList = new ArrayList<>();
Collections.sort(carList);     // compareTo is used to compare, and we have implemented compareTo

We have to change it in the object's class itself. If we need descending at one place and ascending at another, it won't be possible, so we use a Comparator.

Interview corner
When would you use Comparator over Comparable?

When you can't edit the class, or you need more than one order (by name, by price, by date), or a different order at different places.

What happens if you sort objects that aren't Comparable and give no Comparator?

ClassCastException: "cannot be cast to java.lang.Comparable".

How do you sort by two fields?

Comparator.comparing(Person::getName).thenComparing(Person::getAge).

Is Comparator a functional interface?

Yes, it has one abstract method, compare. equals() in it doesn't count because it comes from Object.
