Streams (Java 8)

Process a collection as a pipeline: filter, transform, collect. Very commonly asked in interviews.

What is a stream?

Useful to deal with bulk processing (and it can do parallel processing). Direct practice questions are asked in interviews to do things with a Stream.

Collection
Step 1: create stream
from a data source like a collection or array
Step 2: intermediate operations
filter(), sorted(), map(), distinct() ...
transform the stream into another stream; more operations can be done on top. Lazy.
Step 3: terminal operation
collect(), reduce(), count() ...
triggers the processing and produces the output. Only one terminal operation can be used.

Intermediate operations are lazy in nature: they get executed only when a terminal operation is invoked. Terminal operations trigger the processing of the stream and produce the output. After a terminal operation, no more operations can be performed.

The original data remains unchanged after streaming; the result (new list, array etc.) is separate.

Example

List<Integer> salaryList = new ArrayList<>(Arrays.asList(3000, 4100, 9000, 1000, 3500));

// native way
int count = 0;
for (Integer salary : salaryList) {
    if (salary > 3000) count++;
}
System.out.println(count);    // 3

// using stream
long output = salaryList.stream()
        .filter((Integer sal) -> sal > 3000)
        .count();
  1. The native for loop is faster, because streams have extra overhead: creating the stream pipeline, lambda invocation per element, and possible boxing/unboxing if not a primitive stream (IntStream). But the difference is usually microseconds.
  2. Streams have cleaner, more readable code.
  3. For very huge datasets, parallelStream() helps.

Different ways to create a stream

1. From a collection

List<Integer> salaryList = Arrays.asList(3000, 4100, 9000, 1000, 3500);
Stream<Integer> str = salaryList.stream();

Via Arrays.asList we cannot change the size of the list. If I call list.add(5000) or list.remove(0), Java will throw UnsupportedOperationException at runtime. We may do list.set(0, 5000) to change the value at that index, because Arrays.asList() is a fixed-size view of the underlying array. For a normal (mutable) list: new ArrayList<>(Arrays.asList(3000, 4000)).

List.of(...) (read-only) cannot be modified at all. It is strictly immutable. If we try add(), remove() or even set(), the program will throw UnsupportedOperationException. It doesn't even allow null values, whereas Arrays.asList() allows them. For a normal list: new ArrayList<>(List.of(3000, 4000)).

2. From an array

Integer[] sal = {3000, 4100, 9000, 1000, 3500};
Stream<Integer> str = Arrays.stream(sal);

3. From a static method

Stream<Integer> str = Stream.of(1000, 3500, 4000);

4. From a Stream.Builder

Stream.Builder<Integer> streamBuilder = Stream.builder();
streamBuilder.add(1000).add(9000).add(3500);
Stream<Integer> str = streamBuilder.build();

5. From Stream.iterate

Stream<Integer> str = Stream.iterate(1000, (Integer n) -> n + 5000).limit(5);
//                                  ^ start point
// stream of: 1000, 6000, 11000, 16000, 21000

Intermediate operations

1. filter(Predicate<T>)

Stream<String> nameStream = Stream.of("Hello", "Every", "How", "ARB");
Stream<String> filteredStream = nameStream.filter((String name) -> name.length() <= 3);
List<String> filteredNameList = filteredStream.collect(Collectors.toList());   // [How, ARB]

2. map(Function<T,R>)

Stream<String> filteredNames = nameStream.map((String name) -> name.toLowerCase());
// need a terminal operation too, like collecting to list

3. flatMap(Function<T, Stream<R>>)

Turns a stream of lists into one flat stream.

List<List<String>> sentenceList = Arrays.asList(
    Arrays.asList("I", "LOVE", "JAVA"),
    Arrays.asList("Concepts", "Are", "Clear"),
    Arrays.asList("It", "Is", "Very", "easy")
);

Stream<String> wsl = sentenceList.stream()
        .flatMap((List<String> sentence) -> sentence.stream());
// terminal operation needed. Output: I, LOVE, JAVA, Concepts, Are, Clear, It, ...

Stream<String> ws2 = sentenceList.stream()
        .flatMap((List<String> sentence) -> sentence.stream().map((String value) -> value.toLowerCase()));
// output: i, love, java, concepts ...

4. distinct()

Integer[] arr = {1, 5, 2, 7, 4, 0, 9, 9};
Stream<Integer> allStream = Arrays.stream(arr).distinct();

5. sorted()

Arrays.stream(arr).sorted();

6. peek()

Helps you to see the intermediate result of the stream which is getting processed.

List<Integer> numbers = Arrays.asList(2, 1, 3, 4, 6);
Stream<Integer> numberStream = numbers.stream()
        .filter((Integer val) -> val > 2)
        .peek((Integer val) -> System.out.println(val))     // 3, 4, 6 printed
        .map((Integer val) -> -1 * val);
List<Integer> numberList = numberStream.collect(Collectors.toList());

7. limit(n) and skip(n)

numbers.stream().limit(3);      // truncate the stream to the first 3
numbers.stream().skip(3);       // skips the first n elements of the stream

8. mapToInt() (and mapToLong, mapToDouble)

Helps to work with the primitive int data types.

List<String> numbers = Arrays.asList("2", "1", "4", "7");
IntStream ns = numbers.stream().mapToInt((String val) -> Integer.parseInt(val));
int[] numArray = ns.toArray();

Why are intermediate operations "lazy"?

List<Integer> numbers = Arrays.asList(2, 1, 4, 7, 10);
Stream<Integer> numStream = numbers.stream()
        .filter((Integer val) -> val >= 3)
        .peek((Integer val) -> System.out.println(val));
// Output: nothing would be printed

numStream.count();       // count is one of the terminal operations
// Output: 4  7  10

Sequence of stream operations (it's different than you think)

List<Integer> numbers = Arrays.asList(2, 1, 4, 7, 10);
Stream<Integer> numberStream = numbers.stream()
        .filter((Integer val) -> val >= 3)
        .peek((Integer val) -> System.out.println("after filter: " + val))
        .map((Integer val) -> val * -1)
        .peek((Integer val) -> System.out.println("after negating: " + val))
        .sorted()
        .peek((Integer val) -> System.out.println("after sorted: " + val));
List<Integer> filteredNumberStream = numberStream.collect(Collectors.toList());

Terminal operations

The ones that produce the result. They trigger the processing of the stream.

forEach

numbers.stream().filter((Integer val) -> val >= 3)
       .forEach((Integer val) -> System.out.println(val));

toArray()

Object[] a1 = numbers.stream().filter(val -> val >= 3).toArray();

Integer[] a2 = numbers.stream().filter(val -> val >= 3)
        .toArray((int size) -> new Integer[size]);       // if I want type Integer

reduce()

Performs an associative aggregation function.

Optional<Integer> rv = numbers.stream()
        .reduce((Integer val1, Integer val2) -> val1 + val2);
System.out.println(rv.get());

collect()

List<Integer> fN = numbers.stream().filter(val -> val >= 3)
        .collect(Collectors.toList());

min() and max()

Gives the min or max from the stream based on the comparator.

Optional<Integer> mT1 = numbers.stream()
        .filter(val -> val >= 3)
        .min((Integer val1, Integer val2) -> Integer.compare(val1, val2));   // gives min

Optional<Integer> mT2 = numbers.stream()
        .filter(val -> val >= 3)
        .max((Integer val1, Integer val2) -> Integer.compare(val1, val2));   // gives max

Use max() for the maximum (or .max(Comparator.naturalOrder())). Reversing the comparator inside min() works but is confusing, and the subtraction trick can overflow (see the Comparator chapter).

How many times can we use a single stream?

Once a terminal operation is used on a stream, it is closed / consumed and can't be used again for another terminal operation. We'll have to create a new stream.

Stream<Integer> s = numbers.stream();
s.count();
s.count();     // ✗ IllegalStateException: stream has already been operated upon or closed

Parallel stream

Helps to perform operations on the stream concurrently, taking advantage of a multi-core CPU. The parallelStream() method is used instead of the regular stream() method. Internally it does:

  • Task splitting: it uses a Spliterator to split the data into multiple chunks.
  • Task submission and parallel processing: uses the Fork-Join pool technique.

Good to know: when NOT to go parallel

Parallel streams share one common pool, so they only pay off for big data and CPU-heavy, independent work. For small lists the splitting overhead makes it slower, and lambdas must not mutate shared state or depend on order (use forEachOrdered if you need order). Don't use them for blocking I/O.

Interview corner
map vs flatMap?

map converts each element to one element. flatMap converts each element to a stream and flattens them all into one stream.

Intermediate vs terminal operations?

Intermediate return a stream and are lazy; terminal return a result or nothing and start the pipeline.

Does a stream modify the source collection?

No. It produces a new result; the source is untouched.

Find the second highest salary / group by a field / count words: how?

sorted(Comparator.reverseOrder()).skip(1).findFirst(); collect(Collectors.groupingBy(...)); Collectors.groupingBy(w -> w, Collectors.counting()).

Stream vs Collection?

A collection stores data. A stream is a one-time pipeline over data: it doesn't store anything and can't be reused.
